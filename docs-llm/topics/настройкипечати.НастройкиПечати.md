# Настройки печати

Для печатных форм в формате табличного документа, перед выводом на принтер необходимо выполнить предварительную подготовку: задать ориентацию листа, размеры полей, масштаб, колонтитулы и другие параметры страницы. От этих настроек зависит, как печатная форма будет выглядеть на бумаге: уместится ли таблица в один лист, не «съедутся» ли поля, не обрежется ли часть данных.

### Форма настроек печати

Настройки печати вызываются по кнопке [Иллюстрация] в командной панели над табличным документом на закладке **Макеты**. Открывается стандартный диалог платформы:

[Иллюстрация]
    
Форма «Параметры печати» табличного документа

В диалоге пользователь может настроить:

| Группа параметров | Описание |
|--|--|
| Принтер              | Имя принтера, на котором будет печататься документ. Для каждого принтера сохраняется свой набор настроек |
| Размер бумаги        | Стандартный формат (A3, A4, A5 и т.п.) или произвольный с указанием высоты и ширины в миллиметрах |
| Ориентация           | «Книжная» (вертикальное расположение) или «Альбомная» (горизонтальное) |
| Поля                 | Отступы от края листа: слева, справа, сверху, снизу (по умолчанию 10 мм) |
| Масштаб              | Фиксированное значение в процентах либо «Автомасштаб» — автоматический подбор так, чтобы документ помещался по ширине страницы |
| Колонтитулы          | Размер колонтитулов сверху и снизу (по умолчанию 10 мм) |
| Двусторонняя печать  | Режим печати на одной или двух сторонах листа, количество экземпляров на странице |
| Чередование страниц  | Вариант вывода на печать чередующихся страниц |
| Черно-белая печать | Признак печати таблицы в черно-белом режиме |

Настройки задаются для **конкретного макета табличного документа**.

### Колонтитулы

В диалоге параметров страницы задаётся только **высота полосы** под колонтитул — сверху и снизу, в миллиметрах. Сам текст колонтитула в этот диалог не входит: это отдельное свойство табличного документа.

Текст задаётся алгоритмом в событии ПослеФормирования (см. topic: макрос.ПослеФормирования) — когда печатная форма уже собрана:

```bsl
Колонтитул = ТабличныйДокумент.НижнийКолонтитул;
Колонтитул.Выводить = Истина;
Колонтитул.ВертикальноеПоложение = ВертикальноеПоложение.Верх;
Колонтитул.ТекстСлева  = "[&Дата]";
Колонтитул.ТекстСправа = "Стр. [&НомерСтраницы] из [&СтраницВсего]";
```

Верхний колонтитул задаётся так же — через `ТабличныйДокумент.ВерхнийКолонтитул`; для него привычнее `ВертикальноеПоложение.Низ`, чтобы текст прижимался к таблице.

Свойства колонтитула:

| Свойство | Что задаёт |
|--|--|
| Выводить | Печатать колонтитул или нет |
| ТекстСлева, ТекстВЦентре, ТекстСправа | Три части строки колонтитула: у левого края, по центру, у правого |
| Шрифт | Шрифт всей строки колонтитула |
| ВертикальноеПоложение | Прижать текст к верху, центру или низу полосы колонтитула |
| НачальнаяСтраница | Номер страницы, начиная с которой колонтитул выводится. Например, 2 — чтобы не печатать его на титульном листе |

В тексте работают управляющие конструкции платформы:

| Конструкция | Что подставляется при печати |
|--|--|
| `[&НомерСтраницы]` | Номер текущей страницы |
| `[&СтраницВсего]` | Общее количество страниц |
| `[&Дата]` | Дата печати |
| `[&Время]` | Время печати |

Остальной текст пишется как есть. Значения из наборов данных подставляются в самом алгоритме — обычной сборкой строки.

Если колонтитул задан, а на листе его не видно — проверьте высоту полосы в настройках печати макета: по умолчанию это 10 мм, и длинный текст в неё может не поместиться.

Важно: Событие должно быть именно `ПослеФормирования`. В более ранних событиях документ ещё пустой: при выводе первой области платформа переносит в него параметры печати и колонтитулы исходного документа, и колонтитул, заданный до этого, теряется.

Замечание: Колонтитул — служебная строка на полях листа, вне таблицы. Если шапку или подвал нужно повторять **внутри** таблицы, с данными и оформлением, это делается признаками «Повторять в шапке» и «Повторять в подвале» у области — см. Макет (см. topic: макет.ОбластиМакета). В офисном документе (DOCX) колонтитул собирается иначе — областью со способом вывода «Верхний колонтитул» или «Нижний колонтитул».

### Автоматическое сохранение настроек

Чтобы пользователь не настраивал параметры печати каждый раз заново, в платформе 1С предусмотрен механизм автоматического сохранения. Он работает через специальное свойство табличного документа — **КлючПараметровПечати** (в более старых версиях платформы 8.1 свойство называлось **ИмяПараметровПечати**).

Свойство представляет собой произвольную строку — уникальный идентификатор набора настроек. Конструктор задаёт его автоматически при формировании печатной формы, но разработчик макета может задать собственный ключ, например: `"СчётНаОплату"`, `"АктВыполненныхРабот"`, `"ОтчётПоПродажам"`. Дальше всё происходит автоматически:

* при **открытии** табличного документа платформа смотрит, есть ли в системном хранилище настроек запись с таким ключом для текущего пользователя — и если есть, применяет сохранённые параметры страницы к документу;
* при **изменении** пользователем параметров через форму «Параметры страницы» новые значения автоматически перезаписываются в хранилище под этим же ключом.

Важно: Настройки сохраняются **отдельно для каждого пользователя** информационной базы. Если один сотрудник изменил поля и масштаб для счёта на оплату, это никак не повлияет на печать того же счёта у других пользователей — у каждого свой набор параметров.

Хранятся настройки в **хранилище системных настроек** информационной базы (`ХранилищеСистемныхНастроек`). Это означает, что параметры привязаны не к компьютеру, а к учётной записи пользователя в 1С: при работе с любого рабочего места пользователь увидит свои настройки печати.

### Что это даёт пользователю

Благодаря механизму `КлючПараметровПечати` пользователь один раз настраивает параметры печати для нужной печатной формы — например, выбирает альбомную ориентацию и уменьшенный масштаб для большого отчёта по продажам — и в дальнейшем эти настройки применяются автоматически при каждом формировании этой формы. Не нужно держать в голове, что для одного документа нужна книжная ориентация, для другого — альбомная: программа запомнит выбор и применит его сама.

При этом разные печатные формы (с разными ключами параметров печати) сохраняют свои настройки независимо друг от друга. Можно настроить «Счёт на оплату» для печати на A4 в книжной ориентации, а «Универсальный отчёт» — на A3 в альбомной, и оба варианта будут стабильно работать.

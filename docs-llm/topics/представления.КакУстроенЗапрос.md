# Как устроен запрос

Запрос выше называют *пустышкой*: он ничего не выбирает, а описывает, что нужно получить. Разворачивает его в настоящий запрос сама конфигурация, поэтому каждая часть текста читается механизмом как указание.

| Часть запроса | Что означает |
|--|--|
| `ПОМЕСТИТЬ Представления_<Имя>` | второй сегмент имени временной таблицы — имя представления. Полный список — в справочнике Таблицы представлений (см. topic: представления.таблица.ТаблицыПредставлений) |
| `Представления_<Имя>_<Хвост>` | третий сегмент: для представлений «Срез последних», «Срез первых» и «Таблица регистра» это имя регистра, для остальных — произвольный суффикс. Суффикс нужен, когда одно представление используется в пакете несколько раз: `Представления_КадровыеДанныеСотрудников_ФОТ` и `Представления_КадровыеДанныеСотрудников_Прежние` — это два разных набора полей одного представления |
| поля до `ПОМЕСТИТЬ` | какие поля нужно получить. Значения здесь не важны, важен тип: его задают через `ЗНАЧЕНИЕ(…ПустаяСсылка)`, `ДАТАВРЕМЯ(1, 1, 1)`, `0` и подобные конструкции |
| секция `ИЗ` | временная таблица, ограничивающая выборку, — таблица фильтра (см. topic: представления.ТаблицаФильтра) |
| секция `ГДЕ` | параметры представления, а не условия отбора |

Строки в секции `ГДЕ` — это именно параметры: `"ТолькоРазрешенные" = "ЛОЖЬ"` не сравнивает поле со значением, а говорит механизму, применять ли ограничение доступа к данным. Набор параметров у каждого представления свой; в конструкторе они показаны флажками и полями на закладке «Настройки», а в текст запроса попадают такими строками. Параметр, которого представление не знает, просто игнорируется.

См. также: представления.таблица.ТаблицыПредставлений, представления.ТаблицаФильтра

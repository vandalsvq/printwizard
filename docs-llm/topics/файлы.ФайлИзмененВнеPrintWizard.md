# Файл изменен вне PrintWizard

Связь макета с файлом есть в PrintWizard начиная с версии 2026.4.

Сообщение «Макет записан, файл не обновлен: файл изменен вне PrintWizard.» значит: файл изменился после синхронизации, например пришла правка коллеги из Git.

Другой частый случай — файл в общем каталоге записала другая база.

Такой файл PrintWizard сам не перезаписывает и в макет не загружает: что оставить, решаете вы. Если форма макета открыта, вопрос о выборе появляется сразу после записи. После «Записать и закрыть» вопроса нет — откройте макет снова или выберите в подменю «Связь с файлом» команду «Проверить синхронизацию».

### Как получить правку из репозитория и обновить макет в базе

1. Получите изменения из репозитория в свой каталог (например, `git pull`).
2. Откройте макет. Если включена проверка при открытии, сразу появится вопрос, что оставить; иначе выберите в подменю «Связь с файлом» команду «Проверить синхронизацию».
3. Нажмите «Загрузить из файла» — содержимое файла загрузится в форму.
4. Запишите макет командой «Записать» или «Записать и закрыть».

Какие макеты изменились в файлах, показывает команда «Проверить связи» в форме Синхронизация с файлами (см. topic: файлы.ФормаСинхронизацияСФайлами): связи, которые требуют решения, — сверху списка.

Если макет и файл изменились одинаково — например, ту же правку вы получили из репозитория, — макет в состоянии «Совпадает с файлом», вопроса нет.

### Вопрос о выборе стороны

Текст вопроса называет файл: «Файл <путь> изменен вне PrintWizard.» или, если изменились и макет, и файл, — «Макет изменен и в базе, и в файле <путь>.». Кнопки:

| Кнопка | Что происходит |
|--|--|
| «Загрузить из файла» | Макет в форме заменяется содержимым файла; в базу он попадёт после «Записать». При состоянии «Изменен и в базе, и в файле» изменения макета в базе теряются. Если в форме есть незаписанные изменения, сначала вопрос «Несохраненные изменения в форме будут заменены макетом из файла. Загрузить?» |
| «Записать в файл» | Файл заменяется макетом из базы, изменения файла теряются. В репозитории Git их можно вернуть средствами Git |
| «Сравнить» | Открывается сравнение макетов (см. topic: сравнение.СравнениеМакетов): макет в базе и макет из файла. Ничего не меняется |
| «Отмена» | Ничего не меняется, состояние остаётся. Кнопка по умолчанию |

У заблокированного макета кнопки «Загрузить из файла» нет: загрузка из файла для него недоступна («Макет заблокирован: загрузка из файла недоступна.»). Чтобы принять файл, нажмите «Разблокировать», затем выберите в подменю «Связь с файлом» команду «Проверить синхронизацию» и в вопросе — «Загрузить из файла». Запишите макет и снова заблокируйте его командой «Заблокировать». Пока записанный макет не заблокирован, команды печати у пользователей нет — см. Жизненный цикл макета (см. topic: настройка.ЖизненныйЦиклМакета).

Команда «Загрузить из файла» в подменю «Связь с файлом» загружает связанный файл без диалога. Одноимённая команда подменю «Загрузка / выгрузка» спрашивает, какой файл загрузить, — см. Загрузка из файла (см. topic: списокмакетов.ЗагрузкаИзФайла).

### Файл не найден

Если файла по пути связи нет, макет в состоянии «Файл не найден», и автозапись файл не создаёт: «Макет записан, связанный файл не найден: автозапись его не создает. Записать файл заново можно командой «Записать в файл».». Команда «Проверить синхронизацию» предлагает: «Файл <путь> не найден. Записать макет в файл заново?».

* «Записать в файл» после того же вопроса записывает макет заново по прежнему пути.
* «Снять связь...» после вопроса «Снять связь макета с файлом <путь>? Файл не удаляется.» переводит макет в состояние «Не связан с файлом».

Если файл переименовали или перенесли в другую папку, снимите связь, выделите макет в списке и выполните «Инициализировать каталог» (см. topic: файлы.ИнициализироватьКаталог): команда найдёт файл по ключу макета и свяжет с ним, не перезаписывая.

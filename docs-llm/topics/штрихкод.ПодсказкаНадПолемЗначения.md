# Подсказка над полем значения

Подраздел темы «Конструктор штрихкода» (см. topic: штрихкод.КонструкторШтрихкода).

Над настройками выводятся требования выбранной символики: допустимые символы,
длина, контрольный разряд и пример. Например, для EAN-13:

`EAN13: цифры 0-9, длина 12 или 13, 13-й знак - контрольный, неверный не принимается. Пример: 4601234567893`

Для источника «Поле набора» ниже идёт оценка выбранного поля по его типу —
по строке на каждый тип поля:

| Знак | Смысл | Пример |
|--|--|--|
| ✓ | После приведения к строке значение подойдёт | «✓ Число(13,0) приведётся к 13 цифрам с ведущими нулями» |
| ⚠ | Может не подойти — зависит от конкретного значения | «⚠ Строка(50) может не совпасть с длиной 12 или 13, которую ждёт EAN13» |
| ✗ | Не подойдёт | «✗ Булево не кодируется в EAN13» |

Оценка одного и того же поля зависит от символики. Для ссылочного поля,
например `СтранаПроисхождения` типа «Страна мира», в штрихкод попадает
строковое представление ссылки: символике, которая принимает любые символы
(PDF417), это может подойти — «⚠ Страна мира: в штрихкод попадёт представление
значения», а цифровой (EAN-8) — нет: «✗ Страна мира: представление значения не
подходит EAN8».

[Иллюстрация]
    
Ссылочное поле при символике PDF417: представление может подойти — «⚠»

[Иллюстрация]
    
То же поле при символике EAN-8: цифровой код представление не примет — «✗»

Когда вопросов к полю нет, подсказка зелёная с зелёным флажком; если есть хотя
бы один «⚠» или «✗», она розовая с красным флажком. При заданном формате «✗»
смягчается до «⚠»: формат меняет значение уже после приведения к строке, и
итог проверяется при печати. Для источника «Алгоритм» подсказка советует
возвращать строку.

Подсказка только предупреждает — записать макет она не мешает. Проверить само
значение конструктор не может: из данных документа оно берётся только при
печати.

# Состав полей УФЭБС

[Иллюстрация]
    
QR-код УФЭБС на готовом счёте

УФЭБС — тот самый QR-код, которым счёт оплачивают из банковского приложения.
Формат задан ГОСТ Р 56042-2014: строка кода начинается со служебного заголовка,
дальше идут пары «поле — значение». Строку собирает подсистема «Печать»
(`УправлениеПечатьюРФ.ФорматнаяСтрокаУФЭБС`), ваша работа — сказать, откуда
берётся значение каждого поля.

При выборе типа **«УФЭБС»** состав полей заполняется сам: в таблицу попадают
обязательные (показаны полужирным) и дополнительные платёжные поля. Каждому уже
проставлено ограничение длины по стандарту — слишком длинное значение обрежется,
а не сломает код. Остаётся сопоставить полям значения из наборов данных; строки,
которым значение не задано, в код не попадают.

[Иллюстрация]
    
Конструктор QR-кода, тип «УФЭБС»: слева свойства формата, справа поля наборов, из которых берутся значения

В колонке **«Свойство»** стоит имя поля формата — по нему поле и упоминается
дальше; в колонке **«Имя поля»** — путь к значению в дереве доступных полей.

Важно (Полю сопоставляется строка или число): Значение поля уходит в строку QR-кода как есть, поэтому сопоставлять нужно
**примитивное значение, а не ссылку на объект**: не `Организация`, а
`Организация.Наименование`; не банковский счёт, а его номер. Со ссылкой код может
не сформироваться вовсе, а если сформируется — вместо реквизита в нём окажется
служебный идентификатор, и банковское приложение такой платёж не распознает.

В дереве доступных полей (см. topic: доступныеполя.ДоступныеПоля) ссылочное поле разворачивается —
нужный реквизит выбирается внутри него.

**Обязательные** — без них банковское приложение платёж не распознает. В колонке
«откуда» — пути из счёта на оплату; у вашего макета имена наборов будут своими.

| Свойство | Что это | Длина | Откуда обычно берётся |
|--|--|--:|--|
| `ТекстПолучателя` | Наименование получателя платежа | 160 | `Организация.Наименование` |
| `НомерСчетаПолучателя` | Номер счёта получателя | 20 | `СтруктурнаяЕдиница.НомерСчета` |
| `НаименованиеБанкаПолучателя` | Наименование банка получателя | 45 | `СтруктурнаяЕдиница.Банк.Наименование` |
| `БИКБанкаПолучателя` | БИК банка | 9 | `СтруктурнаяЕдиница.Банк.Код` |
| `СчетБанкаПолучателя` | Корреспондентский счёт банка | 20 | `СтруктурнаяЕдиница.Банк.КоррСчет` |

**Дополнительные** — платёжные реквизиты. Для счёта юридическому лицу обычно
заполняют сумму, назначение платежа и ИНН с КПП; остальные нужны для платежей
в бюджет.

| Свойство | Что это | Длина | Примечание |
|--|--|--:|--|
| `СуммаЧислом` | Сумма платежа | — | В рублях: в формат строки её переводит подсистема «Печать» |
| `НазначениеПлатежа` | Наименование платежа (назначение) | 210 | Самое длинное поле кода — с него начинают, если код получается слишком плотным |
| `ИННПолучателя` | ИНН получателя | 12 | |
| `КПППолучателя` | КПП получателя | 9 | |
| `ИННПлательщика` | ИНН плательщика | 12 | |
| `СтатусСоставителя` | Статус составителя платёжного документа | 2 | Платежи в бюджет |
| `КодБК` | КБК | 20 | Платежи в бюджет |
| `КодОКТМО` | Код ОКТМО | 11 | Платежи в бюджет |
| `ПоказательОснования` | Основание налогового платежа | 2 | Платежи в бюджет |
| `ПоказательПериода` | Налоговый период | 10 | Платежи в бюджет |
| `ПоказательНомера` | Номер документа | 15 | Платежи в бюджет |
| `ПоказательДаты` | Дата документа | 10 | Платежи в бюджет |
| `ПоказательТипа` | Тип платежа | 2 | Платежи в бюджет |

**Прочие** поля стандарта в таблицу сами не попадают — строка добавляется кнопкой
**«Добавить»**, а имя выбирается из списка, где рядом с именем показано его
описание. Это реквизиты плательщика-физлица (фамилия, имя,
отчество, адрес, телефон, документ, удостоверяющий личность) и сведения о
начислении для отраслевых платежей: лицевой счёт, индекс платёжного документа,
СНИЛС, номер договора, срок и период оплаты, вид платежа, показания приборов
учёта, номер извещения, данные учреждения и группы, номер постановления ГИБДД,
уникальный идентификатор начисления. В счёте юридическому лицу они не нужны.

Замечание: Чем больше полей, тем длиннее строка кода и тем плотнее картинка. Если код
перестал читаться телефоном, сокращайте назначение платежа и увеличивайте
**Размер** — настройки ниже.

Настройки: 

* **Погрешность**. Уровень погрешности изображения, при котором данный QR-код все еще возможно 100% распознать;
* **Размер**. Определяет длину стороны выходного изображения в пикселях. Если минимально возможный размер изображения больше этого параметра - код сформирован не будет.

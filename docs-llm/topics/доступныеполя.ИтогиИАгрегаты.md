# Итоги и агрегаты

Для числовых колонок многострочной коллекции программа автоматически строит ветвь `Итог.[Поле]` с набором агрегатов. Считать итоги в запросе, добавлять отдельный набор или писать алгоритм для этого не требуется — достаточно выбрать нужный агрегат в дереве полей.

Агрегаты доступны только для колонок числового типа наборов с видом «Многострочная коллекция». Для количества строк коллекции отдельного агрегата не нужно — есть готовое поле `НаборыДанных.[Набор].КоличествоСтрок`.

| Название в дереве | Сегмент пути | Что считает |
|--|--|--|
| Сумма | `Сумма` | Сумма значений колонки по всем строкам коллекции |
| Среднее | `Среднее` | Среднее значение колонки по всем строкам |
| Максимум | `Максимум` | Наибольшее значение колонки |
| Минимум | `Минимум` | Наименьшее значение колонки |
| Итог накопительный | `ИтогНакопительный` | Нарастающий итог: сумма значений строк, выведенных с начала коллекции |
| Итог по странице | `ИтогПоСтранице` | Сумма значений строк, выведенных на текущей странице; обнуляется при переходе на новую страницу |
| Процент к итогу | `ПроцентКИтогу` | Доля значения текущей строки в общей сумме колонки, в процентах (тип «Число(15,2)») |

Первые четыре агрегата считаются один раз по всей коллекции — их значение одинаково в любой точке печатной формы. Три последних зависят от того, сколько строк уже выведено, поэтому осмысленны в области со способом вывода «По строкам коллекции» и в областях, которые выводятся после неё.

Путь `Итог.[Поле].[Агрегат]` и агрегаты «Итог накопительный», «Итог по странице» и «Процент к итогу» доступны начиная с версии 2026.2.11. Раньше `Итог.[Поле]` означал сумму — такие обращения в алгоритмах переписываются в `Итог.[Поле].Сумма` автоматически при загрузке макета.

### Итог в подвале таблицы

Классическая задача: вывести «Итого» под табличной частью.

1. В области подвала выбираем параметр (например, `ИтогоСумма`) и тип значения «Значение набора».
2. В дереве разворачиваем набор коллекции → ветвь `Итог` → нужную колонку и выбираем агрегат «Сумма».
3. Путь принимает вид `НаборыДанных.Товары.Итог.СуммаСНДС.Сумма`, где `СуммаСНДС` — имя колонки набора, а `Сумма` — имя агрегата.

Так как агрегат считается по всей коллекции, область подвала может выводиться и до строк, и после них — значение не изменится.

### Колонка с нарастающим итогом

Требуется колонка, в которой к каждой строке накапливается сумма предыдущих: 100, 250, 400 и т. д.

1. В макете добавляем в область строки параметр, например `НакопительныйИтог`.
2. Указываем тип значения «Значение набора» и выбираем агрегат «Итог накопительный»: `НаборыДанных.Товары.Итог.Количество.ИтогНакопительный`.

Значение обновляется по мере вывода строк коллекции, поэтому в каждой строке отображается сумма по всем выведенным ранее строкам, включая текущую.

### Итог по странице

Агрегат «Итог по странице» работает так же, как нарастающий итог, но обнуляется после вывода каждой страницы. Типичное применение — строка «Перенос» в конце страницы многостраничной накладной.

Важно: «Итог по странице» доступен только для макетов в формате табличного документа. Для макетов в формате офисного документа (`*.docx`) моменты разрывов страниц определяет сам офисный редактор, программе они неизвестны, поэтому этот агрегат в дереве доступных полей не предлагается. Остальные шесть агрегатов доступны в обоих форматах.

### Процент к итогу

Агрегат «Процент к итогу» возвращает долю значения текущей строки в общей сумме колонки, умноженную на 100. Если сумма колонки равна нулю, возвращается 0.

Например, для колонки `Сумма` со строками 100, 300 и 100 (итог 500) агрегат вернёт 20, 60 и 20 соответственно. Путь: `НаборыДанных.Товары.Итог.Сумма.ПроцентКИтогу`. Тип результата — «Число(15,2)», при необходимости точность вывода настраивается форматированием числа (см. topic: форматирование.ФорматЧисла).

### Итоги в алгоритмах

В отличие от функций поля даты, итоги доступны в произвольных алгоритмах — обращение выполняется по тому же пути, например `НаборыДанных.Товары.Итог.Сумма.Сумма`.

Замечание: Алгоритмы, написанные до версии 2026.2, обращались к сумме как `НаборыДанных.[Набор].Итог.[Поле]` — без имени агрегата. Такие обращения при загрузке макета автоматически приводятся к новой форме `…Итог.[Поле].Сумма`, переписывать алгоритмы вручную не требуется.

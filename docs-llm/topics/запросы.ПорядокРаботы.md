# Порядок работы

Первый запрос писать не приходится. Если на закладке Описание (см. topic: описание.Описание) указан объект метаданных, запросы строятся **сами** — в тот момент, когда вы уходите с «Описания» на любую другую закладку. Программа разбирает объект и создаёт запросы: отдельно шапку, отдельно каждую табличную часть; заодно по ним создаются наборы (см. topic: наборы.Наборы).

Автозаполнение срабатывает, только когда заполнять действительно нечего — запросов или наборов у макета ещё нет. Уже сделанную работу оно не перезаписывает.

Команда **«Заполнить»** в командной панели списка запросов делает то же самое по требованию. Она нужна, когда список запросов надо обновить: например, запрос удалили по ошибке или в объекте метаданных появилась новая табличная часть. Если запросы уже есть, программа спросит, заменить их или дополнить.

Дальше работа идёт так:

1. **Добавьте запрос**, если нужных данных в сгенерированных нет, и дайте ему понятное имя — под этим именем он будет виден на закладке Наборы (см. topic: наборы.Наборы).
2. **Напишите текст запроса** — прямо в поле или через конструктор запросов; проверить результат можно консолью запросов (см. topic: консользапросов.КонсольЗапросов), не выходя из макета.
3. **Проверьте область ошибок и рекомендаций** под текстом (см. Ошибки и рекомендации (см. topic: запросы.ТекстЗапроса)).
4. **Заполните параметры**, если в запросе они есть: кнопка **«Обновить»** над таблицей параметров вычитывает их из текстов запросов.
5. **Обновите поля запроса** — из результата запроса читается состав колонок, без этого поля не из чего будет собрать набор.
6. Переходите на закладку Наборы (см. topic: наборы.Наборы) — там данные запроса превращаются в то, что можно подставить в макет. Наборы подхватывают изменения запросов сами, когда вы уходите с этой закладки.

Возвращаться к запросам по мере отрисовки макета — нормальный ход: состав нужных полей обычно уточняется, когда макет уже виден.

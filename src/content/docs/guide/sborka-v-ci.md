Расширение с печатными формами можно собрать из файлов печатных форм без запуска 1С:Предприятия — в конвейере CI/CD или на компьютере разработчика. Расширение для сборки и сборщик выгружаются из PrintWizard и обновляются после каждого обновления PrintWizard, а само расширение с печатными формами собирается одной командой по файлам форм из репозитория.

## Что нужно для сборки

Собрать расширение с печатными формами в CI или на компьютере разработчика можно без запуска 1С:Предприятия и без рабочей информационной базы — сборщиком `pw-build.os` и утилитой `ibcmd`.

Для сборки нужны:

* **OneScript** 1.9 или 2.x, дополнительные пакеты не нужны;
* **утилита `ibcmd`** из установки платформы 1С:Предприятие — где ее взять, см. [Где взять утилиту](/guide/ch-01-04/#где-взять-утилиту). Версию утилиты сборщик не проверяет: используйте утилиту той версии платформы, на которой работает база, куда ставится расширение;
* **файлы из PrintWizard**: расширение для сборки `PrintWizardBuild.cfe`, сборщик `pw-build.os` и файл настройки сборки `<Имя>.pwbuild.json`, см. [Расширение для сборки](#расширение-для-сборки);
* **файлы печатных форм** `*.xml` или `*.pdwx` — обычно каталог [связи с файлами](/guide/svyaz-s-faylami/) в репозитории Git.

Порядок работы:

1. Выгрузите из PrintWizard файлы для сборки и положите их в репозиторий; после обновления PrintWizard — выгрузите заново.
2. Ведите печатные формы в файлах: PrintWizard обновляет связанный файл при каждой записи макета, остается закоммитить изменения.
3. В конвейере запустите `oscript pw-build.os` — см. [Команда сборки](#команда-сборки).
4. Установите собранный файл `.cfe` в базу — см. [Установка собранного расширения](#установка-собранного-расширения).

Утилита собирает расширение во временной базе, которую сборщик после сборки удаляет. Клиентскую лицензию 1С:Предприятия такая сборка не занимает, см. [Лицензия 1С при сборке](/guide/ch-01-04/#лицензия-1с-при-сборке).

Состав собранного расширения такой же, как у собранного в форме запуска сборки по тем же формам и настройке.

## Расширение для сборки

Выгрузить из PrintWizard для сборки нужно три файла: расширение для сборки — PrintWizard без печатных форм, — сборщик и файл настройки сборки. Выгружают их в базе, где правятся формы, и заново — после обновления PrintWizard.

1. В справочнике «Сборки (PrintWizard)» откройте сборку расширения — с результатом сборки «Расширение (.cfe)».
2. В подменю «Загрузка / выгрузка» (кнопка с пиктограммой) выберите «Расширение для сборки». Команда ничего не выгружает сразу: она открывает форму запуска сборки на варианте «PrintWizard: расширение для сборки (без печатных форм)» с этой сборкой.
3. На вкладке «Расширение» проверьте поля «Поставщик», «Краткая информация» и «Подробная информация»: они заполнены из сборки, их можно изменить.
4. Нажмите «Экспорт». Расширение для сборки собирается так же, как расширение с печатными формами, — тем же [способом сборки](/guide/ch-01-04/#способ-сборки).
5. В окне «Укажите каталог для выгрузки» выберите каталог. По окончании появится оповещение «Выгрузка расширения для сборки завершена»; щелчок по нему открывает каталог.

В каталог выгружаются три файла:

| Файл | Что это |
|--|--|
| `PrintWizardBuild.cfe` | Расширение для сборки: имя `PrintWizardBuild`, синоним «PrintWizard: расширение для сборки», версия — версия PrintWizard, из которого оно выгружено |
| `pw-build.os` | Сборщик — сценарий OneScript |
| `<Имя>.pwbuild.json` | Файл настройки сборки — тот же, что выгружает команда «Настройки в файл» сборки: имя, синоним и версия расширения, печатные формы и пакетные команды сборки |

Поставщика, краткую и подробную информацию собранное расширение берет из расширения для сборки — из полей формы на момент выгрузки. Чтобы их изменить, выгрузите расширение для сборки заново.

Если у пакетной команды сборки в составе меньше двух разных макетов, она в файл настройки не переносится — форма сообщает «Пакетная команда "…" не перенесена: в сборке меньше двух ее разных макетов». В историю версий сборки выгрузка не записывается.

Сборщик собирает только расширение: для сборки с результатом «Обработка (.epf)» команда сообщает «Выгрузка доступна только для сборки расширения», и форма не открывается.

Тот же вариант «PrintWizard: расширение для сборки (без печатных форм)» можно выбрать в форме запуска сборки, открытой из основного меню PrintWizard. Тогда выгружаются только `PrintWizardBuild.cfe` и `pw-build.os`, а файл настройки выгружают отдельно командой «Настройки в файл» в «Сборках». Как выглядит форма на этом варианте — в разделе [Расширение для сборки](/guide/ch-01-04/#расширение-для-сборки) главы «Экспорт в файл».

## Файлы в репозитории

Для сборки в CI в репозитории лежат файлы печатных форм, файл настройки `.pwbuild.json`, расширение для сборки и сборщик; после правки формы обновляется только ее файл.

* **Файлы печатных форм** `*.xml` и `*.pdwx` — обычно каталог [связи с файлами](/guide/svyaz-s-faylami/): PrintWizard записывает в него форму при каждой записи макета. Сборщик обходит каталог форм вместе с подкаталогами и находит форму по ее ключу, а не по имени файла и подкаталогу. Файлы, которые не являются файлами печатных форм PrintWizard, пропускаются.
* **Файл настройки сборки** `<Имя>.pwbuild.json` — состав сборки на момент выгрузки: какие печатные формы входят в расширение (с учетом отборов «Все заблокированные», «Только заблокированные», «Только с командами»), пакетные команды, имя, синоним и версия расширения.
* **`PrintWizardBuild.cfe` и `pw-build.os`** — из одной выгрузки, обновляются вместе.

Что обновить в репозитории после изменения:

| Что изменилось | Что обновить |
|--|--|
| Печатная форма: раскладка, оформление, запросы, команды и объекты печати | Только файл формы: он обновляется при записи макета, остается закоммитить |
| Состав сборки: добавили или убрали печатную форму, изменили пакетную команду, отборы, имя или синоним | Файл настройки — выгрузите «Настройки в файл» заново; для новой формы — и ее файл |
| Поставщик, краткая или подробная информация расширения | Расширение для сборки — выгрузите заново |
| PrintWizard обновлен | Расширение для сборки и сборщик, см. [Когда выгружать расширение для сборки заново](#когда-выгружать-расширение-для-сборки-заново) |

У каждой формы сборки в каталоге должен быть один файл. Если ключ формы найден в двух файлах — например, в связанном файле `.xml` и в файле `.pdwx`, выгруженном разово, — сборка останавливается с сообщением «Несколько файлов печатной формы "…": …».

## Команда сборки

Расширение с печатными формами собирается из командной строки: `oscript pw-build.os` с файлом настройки сборки, каталогом форм и именем собранного файла.

```text
oscript pw-build.os --settings <файл .pwbuild.json> --forms <каталог форм> --out <файл .cfe>
                    [--base <файл .cfe>] [--version <версия>] [--ibcmd <путь>] [--lang ru|en]
```

| Параметр | Значение |
|--|--|
| `--settings` | Файл настройки сборки. Обязательный |
| `--forms` | Каталог файлов печатных форм, с подкаталогами. Обязательный |
| `--out` | Собранный файл расширения. Обязательный |
| `--base` | Расширение для сборки. По умолчанию — `PrintWizardBuild.cfe` в каталоге сборщика |
| `--version` | Версия собранного расширения. По умолчанию — версия из файла настройки |
| `--ibcmd` | Путь к утилите `ibcmd`. По умолчанию — переменная среды `PW_IBCMD`, иначе утилита самой новой установленной платформы |
| `--lang` | Язык сообщений: `ru` (по умолчанию) или `en` |

Значение параметра пишут через пробел или через знак равенства: `--out out/Печать.cfe` и `--out=out/Печать.cfe` равнозначны. Справка — `--help`, `-h` или `/?`; запуск без параметров тоже выводит справку.

**Версия.** В файле настройки записана следующая версия сборки по ее истории — на момент выгрузки файла. Без параметра `--version` все сборки получают эту одну версию, поэтому в CI версию обычно передают параметром, например с номером запуска конвейера.

**Где сборщик ищет утилиту.** Без `--ibcmd` и `PW_IBCMD` утилита ищется в стандартных каталогах установки платформы, из нескольких версий берется самая новая:

* Windows — `%ProgramFiles%\1cv8\<версия>\bin\ibcmd.exe` и тот же путь в `%ProgramFiles(x86)%`;
* Linux и macOS — `/opt/1cv8/x86_64/<версия>/ibcmd`, `/opt/1cv8/aarch64/<версия>/ibcmd` и `/opt/1cv8/<версия>/ibcmd`.

Если на машине сборки установлено несколько версий платформы, задайте `PW_IBCMD` или `--ibcmd` с утилитой той версии, на которой работает база, куда ставится расширение.

Пример шага CI (оболочка `sh`; `BUILD_NUMBER` — номер запуска конвейера в вашей системе CI: GitLab CI, Jenkins, GitHub Actions и других):

```sh
export PW_IBCMD=/opt/1cv8/x86_64/8.3.27.2214/ibcmd   # утилита версии платформы базы

oscript build/pw-build.os \
    --settings build/Печать.pwbuild.json \
    --forms forms \
    --out out/Печать.cfe \
    --version "1.0.0.${BUILD_NUMBER}"
# ненулевой код возврата останавливает шаг
```

Собранный файл может получить права только для владельца и группы: если файл дальше раскладывает другой пользователь, дайте права группе или выполните `chmod`.

**macOS.** OneScript из архива перед первым запуском подпишите локально: `codesign --force -s - oscript`, иначе система завершает его без сообщений. Архивы с кириллическими именами файлов распаковывайте командой `ditto -x -k`, а не `unzip`: `unzip` портит такие имена.

## Журнал сборки

Сборщик выводит журнал сборки в консоль в кодировке UTF-8: какие файлы взяты, какие команды печати собраны, какой утилитой и куда записан результат.

Журнал успешной сборки:

```text
Расширение для сборки: /ci/repo/build/PrintWizardBuild.cfe
Каталог форм /ci/repo/forms: файлов схем 8
Печатная форма "Word Bill": /ci/repo/forms/Продажи/Word Bill.xml
Печатная форма "Счет на оплату": /ci/repo/forms/Продажи/Счет на оплату.xml
Печатная форма "Заказ": /ci/repo/forms/Продажи/Заказ.xml
Команда 2e083987_c159_46b6_9340_7c494ba01d0a "Word Bill": Документ._ДемоСчетНаОплатуПокупателю
Команда 7df75b1e_0b97_4983_9a3b_92736daf0378 "Счет на оплату": Документ._ДемоСчетНаОплатуПокупателю
Команда 0dd772d8_f9ab_4ff9_8a63_8527bd1cc43a "Заказ": Документ._ДемоЗаказПокупателя
Команда d1c498c2_a3ff_4601_bbfc_baefe2e40533 "Комплект": Документ._ДемоСчетНаОплатуПокупателю
Утилита: /opt/1cv8/x86_64/8.3.27.2214/ibcmd
Разбор расширения для сборки утилитой
Расширение для сборки: PrintWizard 2026.4.14.0, схема 6.1
Макет PrintWizardSchema_1 "Word Bill": /ci/repo/forms/Продажи/Word Bill.xml
Макет PrintWizardSchema_2 "Счет на оплату": /ci/repo/forms/Продажи/Счет на оплату.xml
Макет PrintWizardSchema_3 "Заказ": /ci/repo/forms/Продажи/Заказ.xml
Реестр команд PrintWizardCommands: макетов 3, объектов 2, команд 4
Свойства расширения: имя Печать, синоним "Печать", версия 1.0.0.15
Сборка расширения Печать утилитой

```

Что видно в журнале:

* «файлов схем» — сколько файлов печатных форм PrintWizard найдено в каталоге форм;
* «Печатная форма» — какой файл взят для каждой формы из файла настройки;
* «Команда» — каждая команда печати, в том числе пакетная, и объекты, у которых она видна;
* «Расширение для сборки: PrintWizard …, схема …» — из какой версии PrintWizard выгружено расширение для сборки;
* «Свойства расширения» — имя, синоним и версия собранного расширения;
* «Собрано» — сборка завершена, файл записан.

Предупреждения сборку не останавливают — то, о чем они сообщают, в расширение не попадает:

* «Предупреждение: печатная форма "…" (…) уже добавлена» — форма указана в файле настройки дважды;
* «Предупреждение: печатная форма "…" (…) пропущена: ее не печатает ни одна команда»;
* «Предупреждение: пакетная команда "…" пропущена: в сборке меньше двух ее разных макетов»;
* «Предупреждение: пакетная команда "…" пропущена: нет объекта печати, общего для ее макетов»;
* «Файл пропущен: … - архив не читается, пароль .pdwx не поддерживается (…)».

Если расширение не собрано, журнал заканчивается причиной и строкой «Расширение не собрано» — см. [Ошибки сборщика и коды возврата](#ошибки-сборщика-и-коды-возврата).

## Ошибки сборщика и коды возврата

Код возврата сборщика показывает, собрано ли расширение: 0 — собрано, 1 — ошибка входных данных, 2 — ошибка утилиты `ibcmd` или окружения. Причина — в конце журнала, перед строкой «Расширение не собрано».

| Код | Что значит |
|--|--|
| 0 | Расширение собрано, файл `--out` записан |
| 1 | Ошибка входных данных: параметры запуска, файл настройки, файлы печатных форм, расширение для сборки, версия схемы формы |
| 2 | Утилита `ibcmd` не найдена или завершилась с ошибкой, прочие ошибки окружения |

**Файл прошлой сборки.** Собранный файл прошлого запуска сборщик удаляет после проверки параметров, чтения файла настройки и определения версии. Ошибка на этих шагах оставляет прошлый файл на месте, любая ошибка дальше — ни прошлого, ни нового файла. Новый файл появляется только после успешной сборки, поэтому проверяйте код возврата, а не наличие файла. Если `--out` указывает на каталог или совпадает с файлом настройки или расширения для сборки, сборка не начинается.

Сообщения с кодом 1:

| Сообщение | Что сделать |
|--|--|
| «Не задан параметр …, справка - --help», «Неизвестный параметр …», «Не задано значение параметра …», «Неизвестный язык …: допустимы ru и en» | Исправить строку запуска |
| «Файл настройки не найден: …», «Каталог форм не найден: …», «Файл расширения для сборки не найден: …» | Проверить пути `--settings`, `--forms`, `--base` |
| «Параметр --out указывает на каталог: …», «Параметр --out совпадает с входным файлом: …» | Указать в `--out` отдельный файл |
| «Не задана версия: нет параметра --version и ключа version в файле настройки» | Передать `--version` |
| «Файл … не является настройкой сборки расширения (…)» | В `--settings` не файл настройки сборки расширения или он поврежден; в скобках — ключ, на котором проверка не прошла. Выгрузите «Настройки в файл» заново |
| «Печатная форма "…" (…) не найдена в каталоге форм» | Файла формы с этим ключом нет в каталоге: добавьте файл или выгрузите файл настройки заново. В скобках — ключ формы |
| «Несколько файлов печатной формы "…": …» | Оставить в каталоге один файл формы |
| «Файл … старого формата, сборщик его не читает: пересохраните форму в PrintWizard» | Пересохранить форму в PrintWizard |
| «Печатная форма "…" (…) не читается: …» | Файл формы поврежден: запишите макет в PrintWizard заново |
| «В сборке нет ни одной команды печати» | Включить команду печати хотя бы у одной формы сборки |
| «Печатная форма "…" (…) записана PrintWizard новее расширения для сборки (… > …)» | Выгрузить расширение для сборки из обновленного PrintWizard, см. [Когда выгружать расширение для сборки заново](#когда-выгружать-расширение-для-сборки-заново) |
| «Файл не является расширением для сборки: …» | В `--base` не расширение для сборки — например, уже собранное расширение с печатными формами |

Сообщения с кодом 2:

| Сообщение | Что сделать |
|--|--|
| «Утилита ibcmd не найдена: укажите --ibcmd или переменную PW_IBCMD» | Утилита не найдена в стандартных каталогах: задать путь, см. [Команда сборки](#команда-сборки) |
| «Утилита ibcmd не найдена: …» | Нет файла по пути из `--ibcmd` или `PW_IBCMD` |
| «Утилита ibcmd (…) завершилась с кодом …: …» | Причина — в выводе утилиты после двоеточия |

## Когда выгружать расширение для сборки заново

Расширение для сборки и сборщик выгружают заново после каждого обновления PrintWizard в базе, где правятся печатные формы, и заменяют в репозитории оба файла.

Собранное расширение получает исполнитель печатных форм из расширения для сборки — той версии PrintWizard, из которой оно выгружено. Со старым расширением для сборки в собранном расширении остается исполнитель прежней версии, и формы, которые используют возможности нового выпуска, могут печататься не так, как в PrintWizard. Версия видна в журнале сборки: «Расширение для сборки: PrintWizard <версия>, схема <версия>».

Сборщик отказывает в сборке, только если форма записана более новой версией схемы — формата файла печатной формы, — чем расширение для сборки: «Печатная форма "<имя>" (<файл>) записана PrintWizard новее расширения для сборки (<версия схемы формы> > <версия схемы расширения для сборки>)», код возврата 1. Схема меняется не в каждом выпуске PrintWizard, поэтому сборка без этого отказа не значит, что расширение для сборки свежее.

Кроме обновления PrintWizard, расширение для сборки выгружают заново, если нужно изменить поставщика, краткую или подробную информацию расширения. Состав сборки — печатные формы, пакетные команды, имя, синоним — меняет файл настройки, см. [Файлы в репозитории](#файлы-в-репозитории).

## Установка собранного расширения

Установить собранное расширение можно любым способом: в списке «Расширения», в конфигураторе или утилитой `ibcmd` — например, прямо из конвейера CI.

**В списке «Расширения»** («Администрирование» — «Печатные формы, отчеты и обработки» — «Расширения») добавьте расширение из файла или обновите установленное. Для печати форм Word (DOCX) у расширения должен быть снят флажок «Безопасный режим» — проверьте его в списке «Расширения».

**Утилитой `ibcmd`** — тремя командами; `<база>` — параметры подключения к базе: для файловой базы `--db-path=<каталог базы>`, при необходимости `--user` и `--password`:

```text
ibcmd infobase config load <база> --extension=<Имя> <файл .cfe>
ibcmd infobase config apply <база> --extension=<Имя> --force
ibcmd infobase config extension update <база> --name=<Имя> --safe-mode=no
```

Без `--safe-mode=no` утилита оставляет расширение в безопасном режиме, и формы Word (DOCX) не печатаются.

**Права пользователей.** Команды печати пользователи без полных прав видят по роли «PrintWizard: Базовые права» собранного расширения. В конфигурации с подсистемой «Управление доступом» роль сама встает в профили групп доступа с ролью «Базовые права БСП» — при установке в списке «Расширения» сразу, иначе вскоре после входа пользователя в программу; без этой подсистемы роль назначают в карточке пользователя. Подробнее и что делать, если роли нет в профиле, — в разделе [Права пользователей на печать](/guide/ch-09-01/#права-пользователей-на-печать).

Собранное расширение не ставится рядом с полным PrintWizard и с другим расширением, собранным PrintWizard, см. [Ограничения сборки в CI](#ограничения-сборки-в-ci).

## Ограничения сборки в CI

Сборка в CI собирает только расширение с печатными формами, не читает старые и защищенные паролем файлы .pdwx, а собранное расширение не ставится рядом с PrintWizard.

* **Только расширение.** Файл настройки сборки обработки сборщик не принимает: «Файл … не является настройкой сборки расширения (kind)». Обработку (.epf) собирают в форме запуска сборки.
* **Старые файлы .pdwx.** Файлы `.pdwx`, сохраненные PrintWizard до версии 2025.2, не собираются: «Файл … старого формата, сборщик его не читает: пересохраните форму в PrintWizard».
* **Файлы .pdwx с паролем** не поддерживаются: такой файл пропускается; если это файл формы из файла настройки, сборка останавливается сообщением «Печатная форма "…" (…) не найдена в каталоге форм».
* **Одно расширение в базе.** Собранное расширение не подключается рядом с полным PrintWizard, рядом с расширением для сборки и рядом с другим расширением с печатными формами, собранным PrintWizard, — сборщиком или в форме запуска сборки.
* **Команды — как в формах.** Отметки и заголовки команд, измененные в форме запуска сборки, в файл настройки не попадают: сборщик собирает команды такими, какими они заданы в печатных формах, и пакетные команды из файла настройки.
* **Свойства расширения.** Поставщик, краткая и подробная информация берутся только из расширения для сборки: одноименные ключи файла настройки сборщик не читает.
* **Версия утилиты** не проверяется: сборщик берет утилиту, указанную в `--ibcmd` или `PW_IBCMD`, или самую новую из установленных.

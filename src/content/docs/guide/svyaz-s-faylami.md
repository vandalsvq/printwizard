Макет печатной формы можно связать с файлом XML в каталоге на диске — например, в клоне репозитория Git. PrintWizard обновляет файл при записи макета, показывает в форме макета, совпадает ли макет с файлом, и не перезаписывает файл, изменённый вне PrintWizard, без вашего решения.

## Связь макета с файлом

Связь с файлом держит копию макета в файле XML, который обновляется при каждой записи макета: так печатные формы хранятся в Git с историей изменений и переносятся между базами.

Что даёт связь:

* **история изменений в Git** — каталог для файлов обычно клон репозитория системы контроля версий: изменения макета видны в Git сразу после записи, их можно закоммитить, сравнить с прежними версиями и вернуть;
* **перенос между базами** — правку, сделанную в одной базе, другая база получает из того же файла: через репозиторий или общую папку;
* **файл всегда свежий** — выгружать макет вручную после каждой правки не нужно.

Разовая команда «Сохранить в файл» подменю [«Загрузка / выгрузка»](/guide/ch-02-01/#загрузка--выгрузка) работает по-прежнему: она выгружает макет в выбранный файл, но с макетом его не связывает — при следующей записи такой файл не обновляется, и PrintWizard не следит, изменился ли он. Связанный файл у макета один, и PrintWizard знает его путь.

Коммит, получение изменений из репозитория (`pull`), слияние веток выполняются средствами Git: PrintWizard команд Git не вызывает и работает только с файлами в каталоге.

### Как вести историю печатных форм в Git

1. Клонируйте репозиторий на свой компьютер или создайте пустой.
2. В настройках PrintWizard на закладке [«Синхронизация»](#закладка-синхронизация-в-настройках) выберите папку клона в поле «Личный каталог» и ответьте «Да» на вопрос «Инициализировать каталог?» — макеты базы запишутся в каталог и будут связаны с файлами.
3. Закоммитьте файлы средствами Git.
4. Дальше работайте с макетами как обычно: после «Записать» файл обновляется сам, остаётся закоммитить изменения.

Как получить в базу правку коллеги из репозитория — в разделе [Файл изменен вне PrintWizard](#файл-изменен-вне-printwizard).

### Путь и содержимое файла

Путь файла по умолчанию строится из наименований групп справочника и наименования макета с расширением `.xml`: макет «Счет на оплату» в группе «Продажи» записывается в `Продажи/Счет на оплату.xml`. У макета, загруженного из файла, вместо наименования может использоваться имя, записанное в этом файле. Путь можно поправить, когда макет связывается с файлом. Регистр букв в пути не различается: `Счет.xml` и `счет.xml` — один путь. В пути нельзя использовать части «.» и «..», пустые части и символы `:*?"<>|`.

У каждого макета есть постоянный ключ, он записан и в файле. По ключу PrintWizard находит файл макета в каталоге, даже если тот лежит по другому пути: поэтому групповые операции не создают дублей, если у коллеги другая структура папок.

Файл записывается в кодировке UTF-8 без BOM, с переводами строк LF и одинаков на любой операционной системе. Две записи макета без правок дают одинаковые файлы, поэтому Git не видит лишних изменений.

## Личный и общий каталог

Каталог для файлов макетов бывает личным — свой у каждого пользователя на его компьютере, обычно клон Git, — или общим: одна папка на всех пользователей базы, например сетевая.

* **Личный каталог** задаёт себе каждый пользователь, полные права для этого не нужны: папку выбирают на закладке [«Синхронизация»](#закладка-синхронизация-в-настройках) настроек PrintWizard. PrintWizard помнит личный каталог отдельно для каждого компьютера пользователя. Связи макетов с файлами тоже свои у каждого личного каталога.
* **Общий каталог** подключает в базе администратор (пользователь с полными правами). Путь к нему каждый пользователь указывает на своём компьютере: у разных компьютеров он может быть разным, например `\\server\forms` и `Z:\forms`. Пока общий каталог подключён, база работает с ним, а личные каталоги не используются.

Какой вариант выбрать, зависит от того, одна ли база у всех и нужна ли история изменений:

| | Свой каталог у каждого (личный, клон Git) | Один общий каталог |
|--|--|--|
| **Одна база на всех** | Файл пишется в каталог того, кто записал макет, — он же делает коммит. У остальных после получения изменений из репозитория файл совпадает с базой: макет в состоянии «Совпадает с файлом», вопросов нет | Один файл на макет, его пишет база; состояние связи одно на всех пользователей. История изменений есть, если общий каталог сам является клоном Git |
| **У каждого своя база** | Правки переходят между базами через репозиторий: после получения изменений макет в состоянии «Изменен в файле», его загружают командой «Загрузить из файла» | Общая папка форм без Git: правка в одной базе пишет файл, другая база при открытии макета видит «Изменен в файле» и загружает его. Одна форма, изменённая в двух базах, — «Изменен и в базе, и в файле» и выбор стороны. Истории изменений нет |

Чтобы несколько баз работали с одним общим каталогом, администратор каждой базы подключает одну и ту же папку: имя каталога база берёт из файла-метки `printwizard-storage.json` в его корне.

## Закладка «Синхронизация» в настройках

На закладке «Синхронизация» настроек PrintWizard каждый пользователь, и без полных прав, выбирает папку для файлов макетов и флажки автозаписи и проверки при открытии.

Настройки открываются из раздела **PrintWizard → Настройки**, изменения на закладке применяются сразу.

Группа «На этом компьютере»:

| Элемент | Что задаёт |
|--|--|
| Строка общего каталога | «Общий каталог не подключён.» или «Общий каталог «<имя>» подключён.» Администратору доступны ссылки «Подключить...» (каталог не подключён) и «Отключить» (подключён); остальным, пока каталог не подключён, — пояснение «Его подключает администратор.» |
| «Личный каталог» | Папка для файлов макетов на этом компьютере, обычно клон репозитория Git. Видна, пока общий каталог не подключён. Выбирается только кнопкой выбора в поле — диалогом «Выберите личный каталог для файлов макетов», вручную путь не вводится |
| «Путь к общему каталогу» | Путь к подключённому общему каталогу на этом компьютере. Виден, когда общий каталог подключён; тоже выбирается только кнопкой выбора — диалогом «Выберите общий каталог "<имя>"» |
| «Записывать файл при записи макета» | [Автозапись](#запись-файла-при-записи-макета): файл обновляется после «Записать» и «Записать и закрыть». Включён по умолчанию; если выключен — файл пишется командой «Записать в файл» в форме макета |
| «Проверять файл при открытии макета» | Состояние связи пересчитывается при открытии макета: изменения файла после получения из репозитория видны сразу. Включён по умолчанию |

Ссылка «Синхронизация с файлами...» под группой открывает форму [Синхронизация с файлами](#форма-синхронизация-с-файлами).

Личный каталог и путь к общему каталогу PrintWizard помнит для каждого компьютера пользователя, а оба флажка — личные настройки пользователя, одни на все его компьютеры.

**Без полных прав** пользователь на этой закладке выбирает свой личный каталог и путь к общему каталогу, который уже подключил администратор. Подключить или отключить общий каталог может только администратор.

Если в папке, выбранной как путь к общему каталогу, лежит метка другого общего каталога, путь не принимается: «Это другой общий каталог: <имя>». Если метки в папке нет, PrintWizard записывает её заново. Так же восстанавливается метка, пропавшая из папки подключённого общего каталога: пока её нет, операции с файлами каталога не выполняются, и путь нужно выбрать заново в поле «Путь к общему каталогу».

## Первое подключение каталога

Каталог для файлов макетов подключается одним из трёх способов: личный — на закладке «Синхронизация» настроек, общий — администратором там же, или сразу из макета командой «Связать с файлом».

**Личный каталог из настроек.** На закладке [«Синхронизация»](#закладка-синхронизация-в-настройках) выберите папку в поле «Личный каталог». Следом PrintWizard спрашивает: «Инициализировать каталог? Макеты базы будут связаны с файлами каталога по ключу схемы, макеты без файла будут записаны в каталог.» (по умолчанию — «Да»). Ответ «Да» запускает [инициализацию каталога](#инициализировать-каталог) для всех макетов базы и показывает её итог.

**Общий каталог.** Администратор нажимает ссылку «Подключить...» на закладке «Синхронизация» и выбирает папку в диалоге «Выберите общий каталог для файлов макетов».

* В папке нет файла-метки — PrintWizard спрашивает «Имя общего каталога» и записывает в корень папки файл-метку `printwizard-storage.json`. Если папка — клон Git, метку коммитят вместе с формами.
* Метка уже есть — имя берётся из неё. Так вторая база подключает тот же общий каталог.
* В базе уже подключён другой общий каталог — сначала вопрос «В базе подключен общий каталог "<имя>". Подключить вместо него каталог <путь>? …». Связи прежнего общего каталога остаются в списке мест хранения, но не действуют.

После подключения нового общего каталога тот же вопрос «Инициализировать каталог?» предлагает связать с каталогом все макеты базы. Остальные пользователи затем выбирают на своих компьютерах «Путь к общему каталогу» — вопроса об инициализации при этом нет.

Ссылка «Отключить» отключает общий каталог после вопроса «Отключить общий каталог "<имя>"? Пользователи вернутся к личным каталогам. …». Файлы на диске не удаляются.

**Из макета.** Если личный каталог на этом компьютере ещё не задан, команда «Связать с файлом» в форме макета или групповая команда списка сначала открывает диалог «Выберите личный каталог для файлов макетов». Выбранная папка запоминается как личный каталог, вопроса об инициализации нет. Если подключён общий каталог, а путь к нему на этом компьютере не задан, команда сообщает «Путь к общему каталогу не задан на этом компьютере.» — путь выбирается на закладке «Синхронизация».

## Подменю «Связь с файлом»

Подменю «Связь с файлом» на командной панели формы макета показывает, совпадает ли макет с файлом, и собирает команды связи. Надпись и картинка подменю меняются по состоянию связи.

Подменю есть только у записанного макета и нет у [образа для разработки](/guide/ch-02-17/). Подсказка подменю показывает путь файла («Файл: <путь>») и время последней синхронизации («Синхронизировано: <дата и время>»).

| Надпись подменю | Что значит | Команды подменю |
|--|--|--|
| «Связь с файлом» | Состояние не проверено: выключена проверка при открытии макета или файл проверить не удалось. Подсказка — «Синхронизация с файлом не проверена» | «Связать с файлом», «Проверить синхронизацию» |
| «Не связан с файлом» | Макет не связан с файлом в каталоге этого компьютера | «Связать с файлом» |
| «Совпадает с файлом» | Макет в базе и файл одинаковы | «Записать в файл», «Сравнить с файлом», «Проверить синхронизацию» |
| «Изменен в базе» | Макет записан после последней синхронизации, а файл прежний — например, автозапись выключена | «Записать в файл», «Сравнить с файлом», «Проверить синхронизацию» |
| «Изменен в файле» | Файл изменился вне PrintWizard, макет в базе — нет | «Загрузить из файла», «Записать в файл», «Сравнить с файлом», «Проверить синхронизацию» |
| «Изменен и в базе, и в файле» | Изменились и макет, и файл, и они различаются | «Загрузить из файла», «Записать в файл», «Сравнить с файлом», «Проверить синхронизацию» |
| «Файл не найден» | По пути связи файла нет: его удалили, переименовали или перенесли | «Записать в файл», «Проверить синхронизацию», «Снять связь...» |

Последней в подменю, после разделителя, всегда стоит команда «Синхронизация с файлами...» — она открывает [одноимённую форму](#форма-синхронизация-с-файлами). У заблокированного макета команды «Загрузить из файла» нет.

| Команда | Что делает |
|--|--|
| «Связать с файлом» | Связывает макет с файлом в каталоге и сразу записывает макет в файл |
| «Записать в файл» | Записывает макет из базы в связанный файл |
| «Загрузить из файла» | Загружает в форму макет из связанного файла, без диалога выбора файла; в базу — после «Записать». Подробно — в разделе [Файл изменен вне PrintWizard](#файл-изменен-вне-printwizard) |
| «Сравнить с файлом» | Открывает [сравнение макетов](/guide/ch-01-05/): макет из базы и макет из связанного файла. Ничего не меняет |
| «Проверить синхронизацию» | Пересчитывает состояние связи по файлу на диске; если файл изменён вне PrintWizard — предлагает выбрать, что оставить |
| «Снять связь...» | Удаляет связь макета с файлом, файл остаётся на месте |

**Связать с файлом.** Команда спрашивает путь — «Путь файла относительно каталога <каталог>» — и предлагает [путь по умолчанию](#путь-и-содержимое-файла). Если по этому пути уже лежит файл и он отличается от макета, следом вопрос: «Файл <путь> уже есть и отличается от макета в базе. Записать макет из базы поверх файла?». Файл другого макета и файл, который не является схемой печатной формы PrintWizard, команда не перезаписывает никогда: «В файле схема другой печатной формы (ключ <ключ>): запись поверх него запрещена.», «Файл не является схемой печатной формы PrintWizard: запись поверх него запрещена.». Путь, уже связанный с другим макетом, не принимается: «Путь <путь> уже связан с другим макетом в этом месте хранения.».

Если форма изменена и не записана, «Связать с файлом» и «Записать в файл» сначала спрашивают «Макет изменен, а в файл записывается макет из базы. Записать макет и файл?». «Сравнить с файлом» в этом случае спрашивает «Макет изменен, а с файлом сравнивается макет из базы. Записать макет?» и сравнивает записанный макет. При включённой автозаписи «Сравнить с файлом» спрашивает «Макет изменен, а в файл записывается макет из базы. Записать макет и файл?» и вместо сравнения записывает макет и файл.

## Запись файла при записи макета

Связанный файл обновляется сам после записи макета командой «Записать» или «Записать и закрыть», если включён флажок «Записывать файл при записи макета» — по умолчанию он включён.

Перед записью PrintWizard проверяет, что файл не менялся с последней синхронизации. Не менялся — файл перезаписывается, макет переходит в состояние «Совпадает с файлом». Изменён вне PrintWizard или удалён — автозапись файл не трогает: что делать дальше, описано в разделе [Файл изменен вне PrintWizard](#файл-изменен-вне-printwizard).

Если автозапись выключена, после записи макет в состоянии «Изменен в базе», а файл пишется командой «Записать в файл» подменю «Связь с файлом». Флажок — на закладке [«Синхронизация»](#закладка-синхронизация-в-настройках) настроек.

Ошибка записи файла запись макета не отменяет: макет записан, а сообщение «Макет записан, файл не обновлен: <причина>» называет, почему файл остался прежним.

**Проверка при открытии.** Если включён флажок «Проверять файл при открытии макета» (по умолчанию включён), при открытии связанного макета PrintWizard пересчитывает состояние связи по файлу. Так правка, полученная из репозитория, видна сразу: если файл изменён вне PrintWizard, тут же появляется вопрос, что оставить. При выключенном флажке подменю показывает надпись «Связь с файлом», пока не выполнена команда «Проверить синхронизацию» или макет не записан.

Что файл не обновляет:

* **запись макета не из формы** — обменом, обработкой, фоновым заданием. Файл пишется только при записи из формы макета; после записи другим способом макет в состоянии «Изменен в базе», файл обновит команда «Записать в файл» или [«Выгрузить в каталог»](#выгрузить-в-каталог);
* **переименование макета** — путь файла не меняется: связь держится по ключу макета, а не по имени;
* **копирование макета** — копия в состоянии «Не связан с файлом». Имя файла по умолчанию у копии то же, что у исходного макета, поэтому при групповой выгрузке её путь окажется [занят](#занятые-пути-записи).

## Файл изменен вне PrintWizard

Сообщение «Макет записан, файл не обновлен: файл изменен вне PrintWizard.» значит: файл изменился после синхронизации, например пришла правка коллеги из Git.

Другой частый случай — файл в общем каталоге записала другая база.

Такой файл PrintWizard сам не перезаписывает и в макет не загружает: что оставить, решаете вы. Если форма макета открыта, вопрос о выборе появляется сразу после записи. После «Записать и закрыть» вопроса нет — откройте макет снова или выберите в подменю «Связь с файлом» команду «Проверить синхронизацию».

### Как получить правку из репозитория и обновить макет в базе

1. Получите изменения из репозитория в свой каталог (например, `git pull`).
2. Откройте макет. Если включена проверка при открытии, сразу появится вопрос, что оставить; иначе выберите в подменю «Связь с файлом» команду «Проверить синхронизацию».
3. Нажмите «Загрузить из файла» — содержимое файла загрузится в форму.
4. Запишите макет командой «Записать» или «Записать и закрыть».

Какие макеты изменились в файлах, показывает команда «Проверить связи» в форме [Синхронизация с файлами](#форма-синхронизация-с-файлами): связи, которые требуют решения, — сверху списка.

Если макет и файл изменились одинаково — например, ту же правку вы получили из репозитория, — макет в состоянии «Совпадает с файлом», вопроса нет.

### Вопрос о выборе стороны

Текст вопроса называет файл: «Файл <путь> изменен вне PrintWizard.» или, если изменились и макет, и файл, — «Макет изменен и в базе, и в файле <путь>.». Кнопки:

| Кнопка | Что происходит |
|--|--|
| «Загрузить из файла» | Макет в форме заменяется содержимым файла; в базу он попадёт после «Записать». При состоянии «Изменен и в базе, и в файле» изменения макета в базе теряются. Если в форме есть незаписанные изменения, сначала вопрос «Несохраненные изменения в форме будут заменены макетом из файла. Загрузить?» |
| «Записать в файл» | Файл заменяется макетом из базы, изменения файла теряются. В репозитории Git их можно вернуть средствами Git |
| «Сравнить» | Открывается [сравнение макетов](/guide/ch-01-05/): макет в базе и макет из файла. Ничего не меняется |
| «Отмена» | Ничего не меняется, состояние остаётся. Кнопка по умолчанию |

У заблокированного макета кнопки «Загрузить из файла» нет: загрузка из файла для него недоступна («Макет заблокирован: загрузка из файла недоступна.»). Чтобы принять файл, нажмите «Разблокировать», затем выберите в подменю «Связь с файлом» команду «Проверить синхронизацию» и в вопросе — «Загрузить из файла». Запишите макет и снова заблокируйте его командой «Заблокировать». Пока записанный макет не заблокирован, команды печати у пользователей нет — см. [Жизненный цикл макета](/guide/ch-02-01/#жизненный-цикл-макета).

Команда «Загрузить из файла» в подменю «Связь с файлом» загружает связанный файл без диалога. Одноимённая команда подменю «Загрузка / выгрузка» спрашивает, какой файл загрузить, — см. [Загрузка из файла](/guide/ch-02-02/#загрузка-из-файла).

### Файл не найден

Если файла по пути связи нет, макет в состоянии «Файл не найден», и автозапись файл не создаёт: «Макет записан, связанный файл не найден: автозапись его не создает. Записать файл заново можно командой «Записать в файл».». Команда «Проверить синхронизацию» предлагает: «Файл <путь> не найден. Записать макет в файл заново?».

* «Записать в файл» после того же вопроса записывает макет заново по прежнему пути.
* «Снять связь...» после вопроса «Снять связь макета с файлом <путь>? Файл не удаляется.» переводит макет в состояние «Не связан с файлом».

Если файл переименовали или перенесли в другую папку, снимите связь, выделите макет в списке и выполните [«Инициализировать каталог»](#инициализировать-каталог): команда найдёт файл по ключу макета и свяжет с ним, не перезаписывая.

## Выгрузка и инициализация каталога

Команды «Выгрузить в каталог» и «Инициализировать каталог» связывают с файлами каталога сразу группу макетов, выделенных в списке, и показывают итог по каждому макету.

Команды находятся в подменю «Синхронизация с файлами» формы списка макетов — это подменю-картинка без надписи на командной панели, его подсказка — «Выгрузка макетов в каталог и настройка синхронизации с файлами». Там же — команда «Синхронизация с файлами...», которая открывает [одноимённую форму](#форма-синхронизация-с-файлами).

Обе команды работают с выделенными макетами и группами: у выделенной группы — со всеми её макетами. Сами группы, образы для разработки и макеты, помеченные на удаление, пропускаются.

### Выгрузить в каталог

Команда «Выгрузить в каталог» записывает выделенные макеты в файлы каталога и связывает их с файлами; связанные макеты, изменённые в базе, записываются заново.

Команда — в подменю «Синхронизация с файлами» формы списка; у выделенной группы выгружаются все её макеты.

| Макет | Что делает выгрузка |
|--|--|
| Не связан, в каталоге есть файл этого макета (найден по ключу) | Связывает макет с этим файлом по его пути. Если файл отличается от макета, он не трогается: итог «Связан, файл не тронут», выбор стороны — в форме макета |
| Не связан, файла этого макета в каталоге нет | Записывает макет в файл по пути по умолчанию |
| Связан, «Изменен в базе» | Записывает файл |
| Связан, «Совпадает с файлом» | Ничего не пишет |
| Связан, «Изменен в файле», «Изменен и в базе, и в файле» или «Файл не найден» | Пропускает макет, файл не трогает |

Повторная выгрузка без изменений файлы не переписывает. Если ничего не выделено — сообщение «Выделите макеты или группу, которые нужно выгрузить в каталог.».

### Инициализировать каталог

Команда «Инициализировать каталог» связывает макеты базы с файлами уже заполненного каталога — например, когда вы подключаетесь к репозиторию коллег или восстанавливаете связи.

Файл находится по ключу макета, а не по пути, поэтому при другой структуре папок дублей не появляется. Для несвязанного макета:

* файл с его ключом есть и совпадает с макетом — макет связывается с файлом (итог «Связан с файлом каталога»);
* файл есть, но отличается — макет связывается, файл не трогается (итог «Связан, файл не тронут»), выбор стороны — в форме макета;
* файла нет — макет записывается в каталог по пути по умолчанию.

Чего инициализация не делает:

* не перепривязывает уже связанные макеты — только пересчитывает их состояние;
* не записывает связанный макет, изменённый в базе, — для этого есть «Выгрузить в каталог» и «Записать в файл»;
* не загружает в базу файлы, макетов которых в базе нет, — итог «Есть в каталоге, нет в базе»;
* не связывает макет, если в каталоге несколько файлов с его ключом, — итог «Несколько файлов с ключом макета».

Из списка команда работает с выделенными макетами; если ничего не выделено — сообщение «Выделите макеты или группу, которые нужно связать с файлами каталога. Все макеты - в форме "Синхронизация с файлами".». Все макеты базы связывает команда «Инициализировать каталог...» формы [Синхронизация с файлами](#форма-синхронизация-с-файлами) — после вопроса «Связать все макеты базы с файлами каталога <путь>? …», — а также ответ «Да» на вопрос об инициализации после выбора каталога в настройках.

### Окно итога операции

Окно итога групповой операции показывает, что выгрузка или инициализация каталога сделала с каждым макетом: выполнено, пропущено или ошибка.

Окно называется «Выгрузка в каталог: итог» или «Инициализация каталога: итог» и открывается поверх окна, из которого запущена операция; под заголовком указан каталог.

Переключатель «Показать» отбирает строки: «Требуют внимания (N)», «Выполнено (N)», «Все (N)». По умолчанию показаны требующие внимания — пропущенные и ошибки; если таких нет, показаны все строки с оповещением «Требующих внимания нет, показаны все строки.».

Колонки: «Итог» («Выполнено», «Пропущено» или «Ошибка»), «Макет», «Путь», «Результат». Полный текст причины — в поле «Подробно» под списком.

| Команда | Что делает |
|--|--|
| «Записать все» | Записывает поверх файлов все макеты, которые требуют внимания и связаны с файлами, без выделения строк |
| «Записать в файл» | Записывает поверх файлов выделенные макеты |
| «Открыть макет» | Открывает макет текущей строки (то же — двойной щелчок); выбор стороны — при открытии |

Обе команды записи сначала спрашивают, записать ли макеты из базы в файлы, и предупреждают: «Изменения файлов, сделанные вне PrintWizard, будут потеряны.».

### Занятые пути записи

Путь записи занят, если у копий макета одинаковое имя файла или по пути лежит чужой файл: групповая операция тогда ничего не пишет и предлагает исправить пути.

Путь записи занят, если:

* по нему лежит файл другого макета или файл, который не является схемой печатной формы PrintWizard;
* он уже связан с другим макетом;
* его в той же операции уже получил другой макет — так бывает у копий: имя файла по умолчанию у копии то же, что у исходного макета.

Если занятые пути есть хотя бы у части макетов, операция ничего не записывает и открывает окно «<операция>: занятые пути» — например, «Выгрузка в каталог: занятые пути» — со списком этих макетов.

Окно сразу спрашивает: «Пути записи макетов (N) заняты файлами, связями или другими макетами операции. Исправить пути вручную или добавить номер к имени файла?»

| Кнопка | Что происходит |
|--|--|
| «Исправлю сам» | Окно остаётся открытым. Путь правится в колонке «Путь» двойным щелчком (двойной щелчок по другим колонкам открывает макет). Занятые и повторяющиеся пути отмечены. Команда «Выполнить» запускает операцию заново с путями из списка; если пути снова заняты, окно показывает новый список. Кнопка по умолчанию |
| «Добавить номер» | К имени файла добавляется первый свободный номер, начиная с 2: `Счет-2.xml`, `Счет-3.xml`. Первый макет сохраняет имя без номера. Затем операция выполняется. Та же команда есть на панели окна |
| «Отмена» | Окно закрывается, ничего не записано |

Наименование макета номер не меняет — только имя файла.

## Форма «Синхронизация с файлами»

Форма «Синхронизация с файлами» показывает места хранения — каталоги, с которыми работают пользователи базы, — и связи макетов с файлами в каждом из них; в ней проверяют и снимают связи.

Форма открывается командой «Синхронизация с файлами...» из подменю «Синхронизация с файлами» списка макетов, из подменю «Связь с файлом» формы макета и ссылкой на закладке [«Синхронизация»](#закладка-синхронизация-в-настройках) настроек.

Сверху — каталог этого компьютера: «Личный каталог: <путь>», «Общий каталог «<имя>»: <путь>», «Общий каталог «<имя>»: путь на этом компьютере не задан.» или «Каталог на этом компьютере не задан.». Ссылка «Настройки...» открывает настройки PrintWizard на закладке «Синхронизация».

**Места хранения.** Место хранения — личный каталог пользователя на одном компьютере или общий каталог базы. Колонки: «Место хранения», «Пользователь» (видна только администратору), «Компьютер», «Действует», «Связей», «Создано». В колонке «Действует»:

| Значение | Что значит |
|--|--|
| «На этом компьютере» | Место, с которым работает этот компьютер |
| «Подключён в базе» | Общий каталог, подключённый в базе |
| «Другой компьютер» | Личный каталог на другом компьютере — например, прежнем |
| «Отключён» | Общий каталог, который в базе больше не подключён |

**Связи выбранного места хранения.** Колонки: «Состояние», «Макет», «Файл», «Синхронизировано», «Автор». До проверки в колонке «Состояние» — «не проверено»; у связи, макета которой в базе уже нет, в колонке «Макет» — «нет в базе». Колонка «Состояние» — только у места хранения этого компьютера.

| Команда | Что делает |
|--|--|
| «Проверить связи» | Сверяет файлы связей этого компьютера с макетами базы. Связи, которые требуют решения, поднимаются наверх; итог — оповещением «Проверено N: совпадают N, требуют решения N» |
| «Инициализировать каталог...» | [Инициализирует каталог](#инициализировать-каталог) для всех макетов базы после вопроса с путём каталога |
| «Открыть макет» | Открывает макет выбранной связи (то же — двойной щелчок) |

«Проверить связи» и «Инициализировать каталог...» доступны, когда у этого компьютера есть каталог.

Связи и места удаляются стандартной командой «Удалить» (клавиша Del), всегда с вопросом. Файлы на диске не удаляются никогда.

* В списке связей — снять связь у выделенных макетов: «Снять связь с файлами у выделенных макетов (N)? Файлы на диске не удаляются.».
* В списке мест — удалить место со всеми связями, например прежний компьютер: «Удалить место хранения со всеми связями? Файлы на диске не удаляются.». У личного места на его компьютере сбрасываются личный каталог и путь к общему каталогу — их нужно задать заново.
* Подключённый общий каталог удалить нельзя: «Общий каталог подключен в базе: сначала отключите его, затем удалите место хранения.».

**Пользователь без полных прав** видит свои места хранения на всех своих компьютерах и общий каталог; чужие личные места ему не видны. Синхронизироваться с общим каталогом он может, а снять связь у общего места или удалить его — нет: «Изменить общее место хранения может только администратор.».

## Ограничения связи с файлом

Файл связанного макета пишут только формы PrintWizard: запись обменом или обработкой файл не обновляет, образ для разработки с файлом не связывается.

* **Запись не из формы.** Макет, записанный обменом, обработкой или фоновым заданием, остаётся в состоянии «Изменен в базе»: файл пишется только при записи из формы макета, командой «Записать в файл» или групповой [«Выгрузить в каталог»](#выгрузить-в-каталог).
* **Образ для разработки** с файлом не связывается: подменю «Связь с файлом» в его форме нет, а при попытке связать — «Образ для разработки не связывается с файлом: его правки попадают в файл через основной макет.». Команды «Отправить в макет» и «Закрыть образ» с записью изменений записывают файл основного макета, если включена автозапись. Если файл основного макета изменён вне PrintWizard или не найден, он не обновляется — сообщение «Изменения перенесены в основной макет, его файл не обновлен: …», выбор — в форме основного макета командой «Проверить синхронизацию».
* **Пометка на удаление** не удаляет ни файл, ни связь. Файл из репозитория удаляют средствами Git. Групповые операции помеченные макеты пропускают.
* **Один ключ у нескольких макетов.** Такой макет с файлом не связывается: «Ключ макета <ключ> есть и у других макетов: <макеты>. Такой макет не связывается с файлом.».
* **Веб-клиент** работает с файлами только через расширение для работы с файлами; без него — сообщение «Синхронизация с файлами недоступна: не подключено расширение для работы с файлами.», а запись макета не отменяется.

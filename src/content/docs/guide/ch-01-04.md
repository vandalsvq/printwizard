## Экспорт печатных форм

:::caution
Описание форматов экспорта актуально для версии 2025.2 и выше
:::

Все созданные печатные формы в конструкторе могут быть экспортированы во внешний файл одним из следующих способов:

* файл формата **.pdwx** - это формат конструктора PrintWizard. Выгрузка в данном формате может быть использована для:
  * обмена макетами печатных форм
  * сравнения макетов печатных форм между собой
  * печати при помощи обработки **PrintWizard: Исполнитель**
* файл формата **.epf** - это формат внешней обработки. Внешняя обработка может быть выгружена в двух вариантах:
  * полностью автономная (с вложенным **PrintWizard: Исполнитель**)
  * только с печатными формами внутри. При этом **PrintWizard: Исполнитель** должен входить в состав конфигурации, расширения или добавлен как внешняя обработка

Внешние печатные формы выполнены по требованиям БСП. Могут быть открыты самостоятельно или подключены через дополнительные отчеты и обработки.

* файл формата **.cfe** - это формат расширения. Созданное расширение содержит **PrintWizard: Исполнитель**, а также все печатные формы, согласно настройкам выгрузки.

### Экспорт в расширение

Один из основных сценариев разработки, который может быть организован с использованием экспорта в виде расширения:

* создание и доработка печатных форм выполняется на копии базы командой разработчиков;
* готовые макеты переносятся на живую базу по мере подготовки обновлений с определенной периодичностью.

Печатные формы, созданные для тестирования могут быть экспортированы в виде внешних печатных форм. После окончания разработки, они могут быть также включены в новую версию расширения с отключением внешней печатной формы.

Расширение с печатными формами не содержит объектов хранения данных (справочников, документов и т.п.) и может быть в любой момент отключено без потери информации. Более того, данное расширение не требует наличие лицензии на сервере информационной базы, поскольку не содержит возможности редактирования печатных форм.

### Команды печати после обновления расширения

Начиная с версии 2026.4 роль «PrintWizard: Печать» собранного расширения дает права на его печатные формы: команды печати расширения видит и пользователь без полных прав, если у него есть эта роль. В расширении, собранном раньше, роль таких прав не давала, и команды видели только пользователи с полными правами.

:::caution[Обновление расширения, собранного до версии 2026.4]
Если поверх расширения, собранного до версии 2026.4, установить расширение, собранное PrintWizard версии 2026.4 или новее, команды печати, скрытые в настройке подменю «Печать», снова появятся в подменю. Команды теперь принадлежат другой обработке расширения, а скрытие было записано для прежней. Скройте команды заново там же: «Администрирование» — «Печатные формы, отчеты и обработки» — «Подменю "Печать"», см. [Видимость команды](/guide/ch-01-07/#видимость-команды).
:::

### Процесс экспорта

|--|--|--|--|
| Результат сборки          | Выбор результата сборки (внешняя обработка или расширение) | Да | Да |

Пустое значение «Как в настройках пользователя» - способ берется из настроек пользователя в форме запуска сборки. Заполненное значение переопределяет способ пользователя | Да | Да |
| Без встроенного исполнителя | Собрать обработку только с печатными формами, без **PrintWizard: Исполнитель**. | Имя                       | Имя для установки в расширение / обработку | Да | Да |

| Поставщик                 | Наименование поставщика для установки в расширение | Да | Нет |
| Все заблокированные       | Автоматически добавлять все заблокированные макеты. Ручное изменение состава макетов недоступно | Да | Да |
| Только заблокированные    | Добавлять в сборку только заблокированные макеты, из числа выбранных макетов в настройке | Да | Да |
| Только с командами        | Добавлять в сборку только макеты с включенными командами для печати, из числа выбранных макетов в настройке | Да | Да |

Реквизиты «Способ сборки» и «Без встроенного исполнителя» есть в настройке сборки начиная с версии 2026.3.23. У настроек, созданных раньше, способ не задан, а признак «Без встроенного исполнителя» снят: по ним, как и прежде, собирается автономная обработка.

Кроме реквизитов, у настройки сборки есть вкладки: «Макеты» — состав макетов сборки, «Пакетные команды» (начиная с версии 2026.4) — команды, которые печатают комплект из нескольких макетов (см. [Пакетные команды](#пакетные-команды)), и «Расширение» — свойства расширения; вкладка «Расширение» видна только при результате сборки «Расширение (.cfe)». Начиная с версии 2026.4 команды настройки сборки собраны в подменю «Загрузка / выгрузка» (кнопка с пиктограммой) формы настройки и списка сборок:

* «Экспорт сборки» — открывает форму запуска сборки по этой настройке;
* «Настройки в файл» — выгружает настройку сборки в файл `<Имя>.pwbuild.json`. Такой файл готовится для сборки вне 1С.

При выборе признака "Все заблокированные" редактирование состава макетов недоступно. В таком случае, в обработку (или расширение) попадут все заблокированные макеты. Макеты указанные в сборке не обязательно должны быть заблокированы или иметь команды печати. Если не установлены ограничивающие признаки "Только заблокированные" и "Только с командами" они будут добавлены в сборку. К тому же они будут добавлены в команды печати. Поэтому следует внимательно относится к установленным настройкам.

Начиная с версии 2026.4 печатные формы собираются в расширение одной обработкой на все объекты метаданных, синоним обработки — «PrintWizard: печатные формы». Раньше для каждого объекта метаданных собиралась своя обработка. Печатные формы экспортируются в расширение по следующему принципу:

* макеты, которые печатают отмеченные команды сборки, входят в одну обработку; макет, привязанный к нескольким объектам метаданных, входит в нее один раз;
* команды печати добавляются автоматически и видны в подменю «Печать» только у своих объектов метаданных;
* обработка имеет форму, где можно выбрать ссылку и команду печати и выполнить печать. Поле «Ссылка» принимает ссылку любого объекта, для которого собрано расширение: если таких объектов несколько, кнопка выбора сначала спрашивает тип. В поле «Команда» — все команды печати обработки.

### Экспорт в обработку

Экспорт во внешнюю печатную форму может быть выполнен согласно заранее сохраненным настройкам или по произвольной настройке в форме экспорта. При этом историю версий можно хранить только для настроенных вариантов сборок.

Какую обработку собирать по сохраненной настройке - автономную или без исполнителя, - начиная с версии 2026.3.23 определяет признак «Без встроенного исполнителя» настройки сборки: снят - автономная обработка со встроенным **PrintWizard: Исполнитель**, установлен - обработка только с печатными формами.

Настройки сборки обработки соответствуют расширению. При этом в результате, все макеты будут включены в одну обработку, независимо от объектов метаданных (для печати). Команды будут добавлены согласно настройкам макетов конструктора.

### Сборка расширения / обработки

Запустить процесс подготовки и сборки расширения или обработки можно несколькими путями:

* из формы справочника "Макеты" (внешняя печатная форма по указанному макету)
* из формы справочника "Сборки" (согласно текущей настройке сборки) — команда «Экспорт сборки», начиная с версии 2026.4 она в подменю «Загрузка / выгрузка»
* из основного меню PrintWizard (согласно пункту меню)

При этом будет открыта форма запуска сборки:

Начиная с версии 2026.3.23, пока выбрана настройка сборки, поставку в форме описывает настройка:

* вариант сборки, имя, синоним, версия и свойства расширения доступны только для просмотра;
* макеты в форму не добавляются и из нее не удаляются;
* доступными остаются отметки и заголовки команд и способ сборки (на странице "Настройки" в режиме отладки); в дереве команд расширения отметки и заголовки доходят до собранного расширения начиная с версии 2026.4, см. [Команда из нескольких печатных форм](#команда-из-нескольких-печатных-форм);
* выбор другой настройки заменяет макеты, объекты и команды формы составом этой настройки, а не дополняет их.

Так версия, сохраненная в историю по настройке, всегда соответствует самой настройке. Чтобы собрать поставку разово с правками, снимите "Использовать сборку": поля останутся заполненными и станут доступны для изменения.

Начиная с версии 2026.4 сборка обработки или расширения без отмеченных команд печати не начинается: программа сообщает «Не отмечено ни одной команды печати: собирать нечего». Раньше такая сборка давала поставку без команд печати. Для варианта «PrintWizard: Исполнитель (обработка)» команды не нужны, и эта проверка не выполняется.

#### Страница "Обработка / Расширение"

На странице Обработка (или Расширение) доступен выбор макетов для экспорта в файл. 

* для обработки в правой части форма разделена на две табличные части: Объекты метаданных и Команды;
* для расширения в правой части форма содержит дерево: Объекты метаданных > Команды.

##### Команда из нескольких печатных форм

В обработке команду печати можно собрать из нескольких печатных форм. Получится пакетная команда: она формирует сразу все свои печатные формы и показывает их в одном окне печати (подробнее - в разделе [Своя команда пакетной печати](/guide/ch-01-03/#своя-команда-пакетной-печати)).

1. На странице "Обработка" в таблице "Команды" нажмите "Добавить".
2. В списке "Печатные формы" отметьте печатные формы комплекта - не меньше двух - и нажмите "ОК".
3. В новой строке таблицы заполните "Заголовок": под этим заголовком команда появится в подменю "Печать".

Пакетная команда общая для обработки: она появится в подменю "Печать" у всех объектов, для которых собрана обработка. Поэтому собирайте в нее печатные формы одного объекта.

Команды отдельных макетов в таблице удалить нельзя - только снять у них отметку "Использовать". Пакетную команду можно удалить. Если удалить печатную форму из сборки, она уходит и из пакетных команд; команда, в которой осталось меньше двух разных печатных форм, удаляется.

Начиная с версии 2026.4 пакетные команды расширения создаются в настройке сборки — на вкладке «Пакетные команды» справочника «Сборки (PrintWizard)», см. [Пакетные команды](#пакетные-команды). Там же можно задать пакетные команды и для обработки. Когда в форме запуска выбрана настройка сборки, ее пакетные команды переносятся в форму. В дереве команд расширения пакетная команда показана под каждым объектом, у которого она будет видна; добавить или удалить строку в самом дереве нельзя.

Отметки и заголовки команд в дереве команд расширения тоже начиная с версии 2026.4 попадают в собранное расширение; раньше правки в дереве на сборку не влияли. При этом:

* пакетная команда — одна на все объекты: ее отметка и заголовок общие, и правка под одним объектом видна под остальными;
* отметка узла объекта включает или выключает все команды под ним, в том числе пакетные — а значит, и под другими объектами; заголовок узла объекта не правится;
* правки в форме запуска в настройку сборки не записываются.

#### Страница "Настройки"

У обработки есть режим отладки (кнопка "Режим отладки" на командной панели формы). В данном режиме доступна закладка "Настройки": на ней выбирается [способ сборки](#способ-сборки) и указывается каталог сохранения временных файлов (Каталог отладки). Закладка есть только у обработки и расширения: **PrintWizard: Исполнитель** выгружается без сборки, и настраивать для него нечего.

![](/img/ch_01/01_04_3_build_debug_settings.png)
    
Страница "Настройки" в режиме отладки: сборка расширения, способ «Автоматически»

В каталоге отладки после сборки остаются:

* данные исходного расширения или шаблона обработки в XML (каталоги `cfe_old` или `epf_old` соответственно);
* данные готового расширения или обработки в XML (каталоги `cfe_new` или `epf_new` соответственно);
* файлы исходного и готового расширения или обработки (.cfe или .epf соответственно);
* при сборке утилитой - файлы с ее выводом (`ibcmd_*_out.txt` и `ibcmd_*_err.txt`) и каталог данных утилиты `ibcmd_data`. Служебной информационной базы при сборке утилитой нет;
* при сборке расширения конфигуратором - служебная информационная база (каталог `db` или каталог из реквизита "Каталог ИБ").

Рассмотрим подробнее реквизиты на странице "Настройки". Состав страницы зависит от выбранного способа сборки:

| Каталог ИБ                | Путь к каталогу служебной файловой ИБ, в которой конфигуратор собирает расширение. Если каталог не указан, он создается автоматически | Расширение, способ «Конфигуратор» |
| Авторизация               | Признак необходимости авторизации в служебной ИБ | Расширение, способ «Конфигуратор» |
| Имя                       | Имя пользователя служебной ИБ | Расширение, способ «Конфигуратор», установлен признак «Авторизация» |
| Пароль                    | Пароль пользователя служебной ИБ | Расширение, способ «Конфигуратор», установлен признак «Авторизация» |

Команды "Открыть 1С:Конфигуратор" и "Открыть 1С:Предприятие" открывают служебную ИБ и видны вместе с реквизитом "Каталог ИБ". При сборке утилитой служебная ИБ не нужна, поэтому эти реквизиты и команды скрыты. Файл программы при способе «Автоматически» остается на странице: если утилиту найти не удастся, сборка пойдет конфигуратором.

Способ сборки, файл утилиты, потоки выгрузки и кодировка вывода утилиты запоминаются для пользователя: они сохраняются при закрытии формы в режиме отладки и применяются при следующих сборках, в том числе вне режима отладки. Способ, подставленный из настройки сборки, в настройки пользователя не попадает. Дополнительные ключи не запоминаются - их указывают перед каждой сборкой.

#### Страница "Журнал"

Журнал событий, выполненных в процессе подготовки и сборки: дерево событий с колонками "Имя", "Комментарий" и "Время", число событий указано в заголовке закладки.

Начиная с версии 2026.3.23 в журнале видно, чем собран файл:

* событие "ВыбратьСпособСборки" - выбранный способ сборки и откуда он взят: из формы, из настройки сборки или из настроек пользователя. Для утилиты указываются путь к файлу и ее версия, при переходе на конфигуратор - причина: утилита не найдена по пути поиска, не сообщила свою версию или ее версия ниже 8.3.23;
* событие "КомандаУтилиты" - каждый запуск утилиты. При успешном выполнении в комментарии - строка запуска и число предупреждений; предупреждения ошибкой не считаются. При ошибке в комментарий события и в текст ошибки сборки попадают код возврата, вывод утилиты и строка запуска.

![](/img/ch_01/01_04_4_build_log.png)
    
Журнал сборки расширения утилитой: способ взят из настройки сборки, команда утилиты собирает файл из XML

Начиная с версии 2026.4 при сборке расширения в журнале есть событие «ОпределитьОбъектыКоманд» (внутри события «ПодготовитьОбработкуРасширения»): в нем определяется, у каких объектов будет видна каждая [пакетная команда](#пакетные-команды). Если у макетов пакетной команды нет общего объекта печати, событие завершается предупреждением с заголовком команды: «Пакетная команда "…" пропущена: нет объекта печати, общего для ее макетов». Такая команда в расширение не попадает, а сборка продолжается.

Текст ошибки сборки, который видит пользователь, содержит причину ошибки - при сборке и утилитой, и конфигуратором.

### Результат

Всего в результате выполнения обработки можно получить следующие файлы:

* Автономная внешняя печатная форма (.epf) - внешняя печатная форма согласно настройкам из формы. Особенность печатной формы: она может быть добавлена в конфигурацию самостоятельно и не требует наличия никаких дополнительных объектов конструктора;
* Внешняя печатная форма без исполнителя (.epf) - внешняя печатная форма согласно настройкам из формы. Особенность печатной формы: она требует наличия PrintWizard: Исполнитель в составе конфигурации (или расширении) или в дополнительных отчетах и обработках;
* расширение с печатными формами (.cfe) - расширение с печатными формами, а также PrintWizard: Исполнитель в составе.

## Пакетные команды

:::note[Доступно с версии 2026.4]
:::

Пакетная команда в настройке сборки печатает одной кнопкой подменю «Печать» комплект из нескольких макетов — в заданном порядке и числе экземпляров, в расширении и в обработке.

Пакетные команды хранятся в настройке сборки (справочник «Сборки (PrintWizard)») и попадают в каждую поставку, собранную по этой настройке, — и в расширение (.cfe), и в обработку (.epf). В расширение пакетную команду можно добавить только так. В обработку ее можно добавить и разово, в форме запуска сборки: см. [Команда из нескольких печатных форм](#команда-из-нескольких-печатных-форм). Пошаговый пример — в разделе [Пример: комплект документов](/guide/ch-01-03/#пример-комплект-документов).

### Вкладка «Пакетные команды»

Вкладка «Пакетные команды» формы настройки сборки есть при обоих результатах сборки — «Обработка (.epf)» и «Расширение (.cfe)». На ней дерево с колонками «Команда и макеты» и «Экземпляров»: строка команды с ее заголовком, под ней — макеты команды с картинкой формата.

| Кнопка | Что делает |
|--|--|
| «Команда» | Открывает список «Макеты пакетной команды» — макеты из состава сборки с учетом ее отборов. Отметьте не меньше двух макетов: появится новая команда. Ее заголовок — наименования отмеченных макетов через запятую, у каждого макета один экземпляр. Если в сборке меньше двух макетов, программа сообщает «В сборке меньше двух макетов для пакетной команды» |
| «Макет» | Добавляет макеты в конец текущей пакетной команды. В списке только макеты, которых в команде еще нет: повторить макет можно только числом экземпляров |
| Кнопки со стрелками вверх и вниз («Переместить вверх» / «Переместить вниз») | Перемещают макет внутри его команды или команду среди других команд |

Что можно изменить в дереве:

* **заголовок** — только у строки команды: под этим заголовком команда появится в подменю «Печать». Пустой заголовок не принимается;
* **«Экземпляров»** — только у макета: сколько раз макет печатается в комплекте, от 1 до 99;
* **порядок макетов** в команде — это порядок печати комплекта.

Удаление строки команды удаляет команду вместе с ее макетами, удаление строки макета — только этот макет из команды.

### Правила записи пакетной команды

Настройка сборки не записывается, если в пакетной команде:

* меньше двух разных макетов — сообщение «В пакетной команде не меньше двух макетов». Экземпляры одного макета за разные макеты не считаются;
* табличные макеты вместе с макетами Word (DOCX) — сообщение «В пакетной команде макеты одного вида: табличные или Word (DOCX)». Комплект собирается из макетов одного вида: только табличных или только Word.

Сообщение не переводит к строке дерева: найдите команду по заголовку.

### Макет не входит в сборку

Если макет убрать из состава сборки — удалить из таблицы «Макеты» или исключить отбором, — из пакетной команды он не удаляется: в дереве у его строки появляется пиктограмма «Макет не входит в сборку». При сборке такой макет пропускается. Если в команде после этого осталось меньше двух разных макетов, команда в поставку не переносится, а форма запуска сборки сообщает: «Пакетная команда "…" не перенесена: в сборке меньше двух ее разных макетов».

### Каким объектам видна пакетная команда

В расширении пакетная команда видна в подменю «Печать» у объекта, который входит в сборку и указан в таблице [«Объекты метаданных»](/guide/ch-02-03/#объекты-метаданных) закладки «Описание» у каждого макета команды. Признак «Печать» у макета для этого не нужен: достаточно, чтобы объект был указан у всех макетов. Но если в настройке сборки установлен признак «Только с командами», макет без включенной команды печати в сборку не войдет. Объект, у которого есть только пакетные команды, тоже входит в сборку.

Если общего объекта у макетов нет, команда в расширение не попадает: сборка продолжается, а в [журнале сборки](#страница-журнал) событие «ОпределитьОбъектыКоманд» выдает предупреждение «Пакетная команда "…" пропущена: нет объекта печати, общего для ее макетов».

В обработке (.epf), как и раньше, пакетная команда видна у всех объектов, для которых собрана обработка.

### Пакетные команды в форме запуска сборки

Когда в форме запуска сборки выбрана настройка сборки — в том числе при открытии формы командой «Экспорт сборки», — пакетные команды настройки переносятся в форму и для расширения, и для обработки:

* каждый макет повторяется в команде по числу экземпляров — так экземпляры доходят до печати;
* макеты, которые не входят в сборку, отбрасываются;
* команду, в которой осталось меньше двух разных макетов, форма не переносит и сообщает об этом.

При сборке расширения пакетная команда видна в дереве команд под каждым объектом, у которого она будет видна: там можно снять ее отметку или изменить заголовок, см. [Команда из нескольких печатных форм](#команда-из-нескольких-печатных-форм). Правки в форме запуска в настройку сборки не записываются.

В подменю «Печать» пакетная команда формирует макеты в заданном порядке и показывает комплект в одном окне печати; у макета с несколькими экземплярами число копий равно числу экземпляров.

## Способ сборки

:::note[Доступно с версии 2026.3.23]
:::

Обработка и расширение с печатными формами собираются одним из двух способов:

* **утилитой `ibcmd`** из поставки платформы 1С:Предприятия - установленный конфигуратор для этого не нужен;
* **конфигуратором** в пакетном режиме - как в прежних версиях.

Способ определяет только то, чем собирается файл: состав и содержимое обработки или расширения от него не зависят. **PrintWizard: Исполнитель** выгружается без сборки, для него способ не выбирается.

Способ выбирается реквизитом "Способ сборки":

| Значение | Как собирается файл |
|--|--|
| Автоматически | Утилитой, если она найдена и ее версия не ниже 8.3.23; иначе конфигуратором. Значение по умолчанию |
| Утилита ibcmd | Только утилитой. Если утилита не найдена или ее версия ниже 8.3.23, сборка завершается ошибкой с причиной и подсказкой выбрать способ «Конфигуратор» |
| Конфигуратор | Только конфигуратором, как в прежних версиях |

Какой способ выбран и почему, записывается в [журнал сборки](#страница-журнал). Если утилита найдена, но завершилась с ошибкой, способ «Автоматически» не пересобирает файл конфигуратором: ошибка видна в журнале, а способ можно сменить и запустить сборку еще раз.

### Где взять утилиту

Отдельной установки у утилиты `ibcmd` нет: она устанавливается вместе с серверными компонентами платформы.

* **Windows** - компонент «Сервер 1С:Предприятия». Утилита есть на сервере и на рабочем месте, где установлен этот компонент; в поставке тонкого клиента ее нет. 32-разрядная Windows не поддерживается.
* **Linux** - серверные компоненты установщика платформы.
* **macOS** - входит в клиентскую установку платформы.

Утилита ищется там, где идет сборка: на сервере или на клиенте (реквизит "Директива" на странице "Настройки"). По умолчанию - в каталоге платформы 1С:Предприятия на этой стороне; другой файл задается реквизитом "Файл утилиты". Если на стороне сборки утилиты нет - например, на рабочем месте Windows без компонента «Сервер 1С:Предприятия» или с платформой старше 8.3.23, - способ «Автоматически» собирает конфигуратором, как раньше.

### Лицензия 1С при сборке

Сборка утилитой не занимает клиентскую лицензию 1С:Предприятия: утилита не запускает конфигуратор и не подключается к рабочей базе.

Сборка расширения конфигуратором, как и раньше, на время сборки занимает лицензию - и при способе «Конфигуратор», и когда способ «Автоматически» не нашел утилиту. Каким способом собран файл, видно в [журнале сборки](#страница-журнал). Обработка лицензию не занимала и при сборке конфигуратором.

### Где задается способ

Способ сборки задается в двух местах:

* **в настройке сборки** (справочник "Сборки (PrintWizard)") - для конкретной поставки. Значение «Как в настройках пользователя» означает, что способ берется из настроек пользователя;
* **в настройках пользователя** - на [странице "Настройки"](#страница-настройки) формы запуска сборки в режиме отладки.

Способ из настройки сборки переопределяет способ пользователя. В режиме отладки форма показывает итоговый способ, и его можно сменить перед сборкой - например, выбрать «Конфигуратор», если утилита не справилась со сборкой. Вне режима отладки способ в форме не виден: сборка идет способом из настройки сборки, а если в ней способ не задан - способом из настроек пользователя.

## Экспорт в файл .xml (.pdwx)

Файл .xml (также .pdwx) — разовая выгрузка: выгрузить макет в файл и загрузить из файла, чтобы хранить макет или перенести его в другую базу.

Технически файл .pdwx является архивом, внутри которого хранится файл .xml с сериализованными данными.

Начиная с версии 2026.4 макет можно связать с файлом .xml в каталоге — например, в клоне репозитория Git: такой файл обновляется при каждой записи макета, а не выгружается разово. Это описано в главе [Связь с файлами](/guide/svyaz-s-faylami/).

Макет, в котором есть параметр типа [«Штрихкод»](/guide/shtrihkod/), загружается в PrintWizard версии 2026.3.24 и выше: более ранние версии такой файл не прочитают.

Для экспорта в файл *.pdwx перейдите в форму списка или форму элемента макета: в командной панели есть подменю «Загрузка / выгрузка» (кнопка с пиктограммой; до версии 2026.4 оно называлось «Обмен макетами») с командами «Сохранить в файл» и «Загрузить из файла». Что происходит при загрузке файла в базу — создать новый макет, заменить им существующий или сравнить с ним — разобрано в разделе [Загрузка из файла](/guide/ch-02-02/#загрузка-из-файла).

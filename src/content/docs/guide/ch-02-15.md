Дерево доступных полей — это единый список значений, которые можно подставить в печатную форму: в параметр области макета, в правило вывода области, в конструктор представления, в поле нумератора и в другие места, где требуется указать «откуда взять значение». Кроме обычных полей наборов в этом дереве есть значения, которые программа вычисляет самостоятельно: функции по полю даты, итоги и агрегаты по числовым колонкам многострочных коллекций, а также системные поля.

Эта глава посвящена именно таким, вычисляемым, полям. Она отвечает на вопросы вида «как вывести месяц документа», «как сделать колонку с нарастающим итогом», «как получить процент строки к итогу таблицы» и «как вывести фамилию в родительном падеже» — то есть на задачи, которые часто пытаются решить произвольным алгоритмом, хотя достаточно выбрать нужное поле в дереве. Здесь же описан ввод пути поля текстом — без поиска в дереве.

Базовые сведения о наборах и их полях описаны в разделе [Наборы данных](/guide/ch-02-05/), о связывании наборов — в разделе [Соединения](/guide/ch-02-06/), о параметрах и условиях вывода областей — в разделе [Макет](/guide/ch-02-07/).

## Формы пути поля

Любое доступное поле — это путь, который однозначно указывает на значение. В параметре области, в правилах вывода и в конструкторах параметров области путь начинается с `НаборыДанных`. В конструкторах, открытых от поля набора, — поля представления, нумератора, контактной информации — путь начинается с имени поля этого набора: `Организация.ИНН`. Форма пути зависит от того, откуда берётся значение.

| Путь | Что это |
|--|--|
| `НаборыДанных.[Набор].[Поле]` | Поле набора с видом «Первая строка», «Последняя строка» или «Соединение строк» |
| `НаборыДанных.[Набор].Строка.[Поле]` | Поле строки многострочной коллекции; доступно в области, для которой этот набор указан в колонке «Набор» |
| `НаборыДанных.[Набор].Итог.[Поле].[Агрегат]` | Итог по числовой колонке многострочной коллекции |
| `НаборыДанных.[Набор].КоличествоСтрок` | Количество строк многострочной коллекции |
| `НаборыДанных.[Набор].[Соединение].[Поле]` | Поле правого набора, полученное через соединение с видом «Первая строка», «Последняя строка» или «Соединение строк» |
| `НаборыДанных.[Набор].[Соединение].КоличествоСтрок` | Количество строк, отобранных соединением с видом «Многострочная коллекция» |
| `НаборыДанных.[Набор].[Соединение].Итог.[Поле].[Агрегат]` | Итог по числовой колонке строк, отобранных соединением с видом «Многострочная коллекция» |
| `НаборыДанных.СистемныеПоля.[Поле]` | Системное поле, которое программа заполняет сама |

Подробное описание форм пути и правил видимости полей приведено в разделе [Наборы данных](/guide/ch-02-05/#типы-полей-набора), пути через соединение — в разделе [Поля соединений](#поля-соединений). Здесь важно другое: к пути поля может добавляться ещё один сегмент — имя функции (для полей типа «Дата») или имя агрегата (для числовых колонок коллекции). Эти сегменты и описаны ниже.

Поле выбирается в форме «Доступные поля». В дереве две колонки: «Путь к данным» — представление узла с пиктограммой типа данных — и колонка с пиктограммой принтера, где флажком отмечены поля простого типа, которые рекомендуется выводить в печатную форму. Над деревом расположена строка поиска. Дерево заполняется по мере разворачивания узлов: вложенные реквизиты ссылочного поля и функции поля даты подставляются в момент, когда узел разворачивается. Путь поля можно и не искать в дереве: начиная с версии 2026.4 его вводят или вставляют текстом в само поле выбора, см. [Ввод пути текстом](#ввод-пути-текстом).

![](/img/ch_02/84_fields_tree.png)
    
Форма «Доступные поля»

Состав дерева зависит от места вызова: например, построчные поля многострочной коллекции предлагаются только там, где построчный вывод применим. Отдельно ограничивать список не требуется.

Кроме представления, у дерева есть служебные колонки «Тип данных» и «Полный путь». По умолчанию они скрыты и нужны в основном для диагностики — когда требуется убедиться, какой именно путь подставится в макет. Вывести их можно стандартной командой платформы «Ещё» → «Изменить форму».

## Ввод пути текстом

:::note[Доступно с версии 2026.4]
:::

Поле набора не обязательно выбирать в дереве доступных полей: в поле выбора можно ввести или вставить его полный путь, например `НаборыДанных.Шапка.Организация.ИНН`. Когда ввод закончен, поле подставляется так же, как при выборе в дереве, — запись макета и печать не отличаются. Выбор в дереве остаётся — кнопкой «…» в том же поле. Выпадающий список полей первого уровня у этих полей убран: подбор появляется при наборе текста.

Путь принимают такие поля:

| Форма | Поле | Путь начинается с |
|--|--|--|
| Параметр области на закладке «Макет», тип «Значение набора» | «Значение», [подробнее](/guide/ch-02-07/#ввод-пути-текстом) | `НаборыДанных` |
| «Правила вывода областей» | Колонка «Левое значение» | `НаборыДанных` |
| «Конструктор представления» от параметра области с типом «Конструктор строки» | Колонка «Имя поля» | `НаборыДанных` |
| «Конструктор представления» от поля набора с типом «Поле представления» | Колонка «Имя поля» | имени поля |
| «Конструктор QR-кода» | Колонка «Имя поля» | `НаборыДанных` |
| «Конструктор штрихкода», источник значения «Поле набора» | «Значение» | `НаборыДанных` |
| «Конструктор суммы прописью» | «Значение» и «Валюта» | `НаборыДанных` |
| «Конструктор нумератора» | Колонка таблицы полей (без заголовка) | имени поля |
| «Конструктор конт. информации» | «Период» | имени поля |

В конструкторах, открытых от поля набора, путь пишется без `НаборыДанных` и имени набора: `Организация.ИНН`. Там предлагаются только поля того же набора, кроме полей представления, а реквизиты через точку есть только у полей типа «Поле источника»: у поля алгоритма ссылочного типа реквизитов нет ни в подборе, ни в дереве.

### Подбор при наборе

Пока путь набирается, список подбора подсказывает поля — не больше 20 строк, в каждой полный путь с пиктограммой типа:

* пока текст не продолжает путь доступного поля через точку, он ищется в путях доступных полей: `Шапка.Орг` найдёт `НаборыДанных.Шапка.Организация`; слова через пробел ищутся по отдельности, в том же порядке;
* после пути поля и точки список показывает вложенные поля этого поля, а следующие буквы их отбирают: в имени должны встретиться все набранные слова, по порядку, регистр не важен.

Раскрывается то же, что в дереве: ссылочное поле — в реквизиты на любую глубину, поле набора с типом даты — в функции даты. У реквизита-даты ссылочного поля, у самой функции и у остальных полей вложенных полей нет. Табличных частей и реквизита `Ссылка` в пути нет, как нет их и в дереве.

![](/img/ch_02/100_path_suggest_barcode.png)
    
Конструктор штрихкода: реквизиты поля «ГруппаДоступа» после точки

Функция даты вводится последним сегментом полного пути — названием из раздела [Функции поля даты](#функции-поля-даты) без пробелов: `НаборыДанных.Шапка.Дата.НачалоМесяца`. Функция попадает на печать из «Значения» параметра области и «Левого значения» правил вывода. В конструкторах штрихкода, представления, QR-кода, суммы прописью, нумератора и конт. информации подбор тоже показывает функции, но на печать функция там не попадает — указывайте само поле даты. После точки за полем даты список показывает первые 20 функций из 23; «Неделя года», «Месяц» и «Год» появятся, если начать набирать имя.

### Окончание ввода

Когда ввод закончен, программа ищет поле по порядку:

1. Доступное поле, путь которого совпадает с текстом целиком, — даже если есть более длинные пути, которые с него начинаются.
2. Вложенное поле — от самого длинного доступного пути, с которого начинается текст.
3. Поля, в пути которых встречается текст, — как при подборе.

Регистр букв не важен: в значение записываются имена из конфигурации. Последнее имя пути сравнивается целиком, поэтому незаконченное `НаборыДанных.Шапка.Организация.ИН` не подставит `ИНН`, а даст сообщение об ошибке.

### Ошибка в пути

Если путь разошёлся с составом данных, значение поля не меняется, а в панели «Сообщения» внизу формы появляется подсказка: на каком имени путь разошёлся и какие имена есть на этом уровне. Например, для `НаборыДанных.Шапка.Организация.Кодд`:

«Нет поля «Кодд» у «Организация». Доступны: ИмяПредопределенныхДанных, Предопределенный, ПометкаУдаления, Наименование, Код, ОбластьДанныхОсновныеДанные, БИК, ГлавныйБухгалтер, Директор, ИндивидуальныйПредприниматель и ещё 17»

После «у» стоит имя последнего найденного поля. Перечисляется не больше 10 имён: сначала те, в которых встречается введённое имя, затем остальные в порядке конфигурации; об остальных — «и ещё N». При ошибке в имени функции даты перечисляются функции. Второй текст — «У поля «ИНН» нет вложенных полей»: путь продолжается после поля, у которого вложенных полей нет, например `НаборыДанных.Шапка.Организация.ИНН.Код`.

Пока ввод не закончен, платформа может показать под полем «"НаборыДанн..." не найдено.» — это пустой список подбора, а не ошибка пути.

![](/img/ch_02/101_path_typing_not_found.png)
    
Ввод ещё не закончен: в списке подбора нет совпадений

![](/img/ch_02/102_path_error_message.png)
    
Ввод закончен: значение не подставлено, в панели «Сообщения» — подсказка

Значение не меняется и без сообщения, если:

* путь не начинается ни с одного доступного поля — например, с `НаборыДанных` в конструкторе, открытом от поля набора, или с имени поля там, где нужен полный путь;
* текст кончается точкой — ввод считается незаконченным;
* в пути есть пустой сегмент — две точки подряд.

В конструкторе суммы прописью «Значение» и «Валюта» сообщают об ошибке каждое отдельно.

## Функции поля даты

Функция поля даты — это преобразование значения даты, которое выполняется в момент вывода. Оно не требует ни изменения запроса, ни произвольного алгоритма: достаточно развернуть в дереве узел поля с типом «Дата» и выбрать нужную функцию. Имя функции добавляется к пути поля отдельным сегментом: `НаборыДанных.Заказ.Дата.НачалоМесяца`. Сегмент образуется из названия функции без пробелов: «Начало месяца» → `НачалоМесяца`, «День недели» → `ДеньНедели`. Начиная с версии 2026.4 функцию можно ввести последним сегментом полного пути — `НаборыДанных.Заказ.Дата.НачалоМесяца` — в «Значении» параметра области и «Левом значении» правил вывода, см. [Ввод пути текстом](#ввод-пути-текстом).

Функции делятся на две группы: усечение даты (результат — дата) и извлечение части даты (результат — число).

### Усечение даты

Возвращают дату: исходное значение, «обрезанное» до начала или конца периода. Например, для значения `15.05.2026 14:37:52` функция «Начало месяца» вернёт `01.05.2026 00:00:00`, а «Конец месяца» — `31.05.2026 23:59:59`.

| Название в дереве | Значение в XML | Что возвращает |
|--|--|--|
| Начало минуты | `BegOfMinute` | Дата — начало минуты |
| Начало часа | `BegOfHour` | Дата — начало часа |
| Начало дня | `BegOfDay` | Дата — начало суток |
| Начало недели | `BegOfWeek` | Дата — начало недели (понедельник) |
| Начало месяца | `BegOfMonth` | Дата — первое число месяца |
| Начало квартала | `BegOfQuarter` | Дата — первое число квартала |
| Начало года | `BegOfYear` | Дата — 1 января |
| Конец минуты | `EndOfMinute` | Дата — последняя секунда минуты |
| Конец часа | `EndOfHour` | Дата — последняя секунда часа |
| Конец дня | `EndOfDay` | Дата — последняя секунда суток |
| Конец недели | `EndOfWeek` | Дата — последняя секунда воскресенья |
| Конец месяца | `EndOfMonth` | Дата — последняя секунда месяца |
| Конец квартала | `EndOfQuarter` | Дата — последняя секунда квартала |
| Конец года | `EndOfYear` | Дата — последняя секунда 31 декабря |

### Извлечение части даты

Возвращают число — соответствующую часть даты.

| Название в дереве | Значение в XML | Что возвращает |
|--|--|--|
| Секунда | `Second` | Число: секунда (0–59) |
| Минута | `Minute` | Число: минута (0–59) |
| Час | `Hour` | Число: час (0–23) |
| День | `Day` | Число: день месяца (1–31) |
| День недели | `WeekDay` | Число: день недели (1 — понедельник, 7 — воскресенье) |
| День года | `DayOfYear` | Число: день года (1–366) |
| Неделя года | `WeekOfYear` | Число: номер недели в году |
| Месяц | `Month` | Число: месяц (1–12) |
| Год | `Year` | Число: год |

Всего доступно 23 функции. Значения в колонке «Значение в XML» — это то, что записывается в элемент `<FunctionName>` при экспорте макета; полный перечень со стороны объектной модели приведён в разделе [Объектная модель и API](/model/ch-01-02/#перечисления).

:::note
Функция вычисляется программой при подготовке значения к выводу — на этапе, когда параметр области или правило вывода обращается к полю. Поэтому в произвольных алгоритмах путь с функцией использовать нельзя: в структуре данных печати такого поля нет, там доступно только исходное значение поля набора.
:::

### Пример: вывести месяц документа в заголовке

Требуется вывести в шапке отчёта период вида «май 2026», а сам документ содержит поле `Дата` с временем.

1. В области с заголовком выбираем параметр и тип значения «Значение набора».
2. В дереве доступных полей разворачиваем поле `Дата` набора и выбираем функцию «Начало месяца» — путь становится `НаборыДанных.Заказ.Дата.НачалоМесяца`.
3. В колонке форматирования задаём [формат даты](/guide/ch-02-12/#формат-даты) с выводом месяца и года.

Функция отвечает только за значение. Если требуется сгруппировать сами строки табличной части по месяцам, группировка выполняется в запросе набора — функция поля этого не заменяет.

### Пример: вывести день недели

Функция «День недели» возвращает число (1 — понедельник). Если в печатной форме нужен день недели прописью, удобнее взять функцию «Начало дня» и задать для поля [формат даты](/guide/ch-02-12/#формат-даты) с выводом дня недели: значение остаётся датой, а прописное представление формирует форматирование. Числовой результат «Дня недели» подходит там, где день недели нужен именно как число — например, в правиле вывода области.

### Пример: сравнение по дате без учёта времени

Поле даты документа почти всегда содержит время, поэтому прямое сравнение «Дата равно 15.05.2026» не сработает: значение `15.05.2026 14:37:52` не равно `15.05.2026 00:00:00`. Функция «Начало дня» решает эту задачу — в [правиле вывода области](/guide/ch-02-07/#условия-вывода-области) в качестве левого значения выбирается `НаборыДанных.Заказ.Дата.НачалоДня`:

| Использование | Левое значение | Вид сравнения | Значение |
|--|--|--|--|
| ✓ | `НаборыДанных.Заказ.Дата.НачалоДня` | Равно | `15.05.2026` |

Так же работают сравнения «больше или равно» с началом месяца, квартала или года.

## Итоги и агрегаты

Для числовых колонок многострочной коллекции программа автоматически строит ветвь `Итог.[Поле]` с набором агрегатов. Считать итоги в запросе, добавлять отдельный набор или писать алгоритм для этого не требуется — достаточно выбрать нужный агрегат в дереве полей.

Агрегаты доступны только для колонок числового типа наборов с видом «Многострочная коллекция». Под соединением с тем же видом из них есть только сумма, среднее, максимум и минимум — см. [Поля соединений](#поля-соединений). Для количества строк коллекции отдельного агрегата не нужно — есть готовое поле `НаборыДанных.[Набор].КоличествоСтрок`.

| Название в дереве | Сегмент пути | Что считает |
|--|--|--|
| Сумма | `Сумма` | Сумма значений колонки по всем строкам коллекции |
| Среднее | `Среднее` | Среднее значение колонки по всем строкам |
| Максимум | `Максимум` | Наибольшее значение колонки |
| Минимум | `Минимум` | Наименьшее значение колонки |
| Итог накопительный | `ИтогНакопительный` | Нарастающий итог: сумма значений строк, выведенных с начала коллекции |
| Итог по странице | `ИтогПоСтранице` | Сумма значений строк, выведенных на текущей странице; обнуляется при переходе на новую страницу |
| Процент к итогу | `ПроцентКИтогу` | Доля значения текущей строки в общей сумме колонки, в процентах (тип «Число(15,2)») |

Первые четыре агрегата считаются один раз по всей коллекции — их значение одинаково в любой точке печатной формы. Три последних зависят от того, сколько строк уже выведено, поэтому осмысленны в области со способом вывода «По строкам коллекции» и в областях, которые выводятся после неё.

Путь `Итог.[Поле].[Агрегат]` и агрегаты «Итог накопительный», «Итог по странице» и «Процент к итогу» доступны начиная с версии 2026.2.11. Раньше `Итог.[Поле]` означал сумму — такие обращения в алгоритмах переписываются в `Итог.[Поле].Сумма` автоматически при загрузке макета.

### Итог в подвале таблицы

Классическая задача: вывести «Итого» под табличной частью.

1. В области подвала выбираем параметр (например, `ИтогоСумма`) и тип значения «Значение набора».
2. В дереве разворачиваем набор коллекции → ветвь `Итог` → нужную колонку и выбираем агрегат «Сумма».
3. Путь принимает вид `НаборыДанных.Товары.Итог.СуммаСНДС.Сумма`, где `СуммаСНДС` — имя колонки набора, а `Сумма` — имя агрегата.

Так как агрегат считается по всей коллекции, область подвала может выводиться и до строк, и после них — значение не изменится.

![](/img/ch_02/85_fields_total.png)
    
Ветвь «Итог» у колонки коллекции: список агрегатов

### Колонка с нарастающим итогом

Требуется колонка, в которой к каждой строке накапливается сумма предыдущих: 100, 250, 400 и т. д.

1. В макете добавляем в область строки параметр, например `НакопительныйИтог`.
2. Указываем тип значения «Значение набора» и выбираем агрегат «Итог накопительный»: `НаборыДанных.Товары.Итог.Количество.ИтогНакопительный`.

Значение обновляется по мере вывода строк коллекции, поэтому в каждой строке отображается сумма по всем выведенным ранее строкам, включая текущую.

### Итог по странице

Агрегат «Итог по странице» работает так же, как нарастающий итог, но обнуляется после вывода каждой страницы. Типичное применение — строка «Перенос» в конце страницы многостраничной накладной.

:::caution
«Итог по странице» доступен только для макетов в формате табличного документа. Для макетов в формате офисного документа (`*.docx`) моменты разрывов страниц определяет сам офисный редактор, программе они неизвестны, поэтому этот агрегат в дереве доступных полей не предлагается. Остальные шесть агрегатов доступны в обоих форматах.
:::

### Процент к итогу

Агрегат «Процент к итогу» возвращает долю значения текущей строки в общей сумме колонки, умноженную на 100. Если сумма колонки равна нулю, возвращается 0.

Например, для колонки `Сумма` со строками 100, 300 и 100 (итог 500) агрегат вернёт 20, 60 и 20 соответственно. Путь: `НаборыДанных.Товары.Итог.Сумма.ПроцентКИтогу`. Тип результата — «Число(15,2)», при необходимости точность вывода настраивается [форматированием числа](/guide/ch-02-12/#формат-числа).

### Итоги в алгоритмах

В отличие от функций поля даты, итоги доступны в произвольных алгоритмах — обращение выполняется по тому же пути, например `НаборыДанных.Товары.Итог.Сумма.Сумма`.

:::note
Алгоритмы, написанные до версии 2026.2, обращались к сумме как `НаборыДанных.[Набор].Итог.[Поле]` — без имени агрегата. Такие обращения при загрузке макета автоматически приводятся к новой форме `…Итог.[Поле].Сумма`, переписывать алгоритмы вручную не требуется.
:::

## Поля соединений

Поля набора, подключённого [соединением](/guide/ch-02-06/), доступны через левый набор. В дереве под левым набором появляется узел с именем соединения, а путь к полю идёт через имя соединения, а не через имя правого набора: `НаборыДанных.[Левый набор].[Имя соединения].[Поле]`.

Начиная с версии 2026.4 дерево показывает все поля соединения, и выбрать их можно везде, где выбирается поле области, — в дереве и [вводом пути](#ввод-пути-текстом): в параметре области, в правилах вывода, в конструкторе представления, в конструкторах QR-кода, штрихкода и суммы прописью. В более ранних версиях из полей соединения в дереве были только количество строк и итоги, и только у соединений набора-коллекции.

Что доступно под соединением, зависит от его вида набора:

| Вид соединения | Что доступно | Путь |
|--|--|--|
| «Первая строка», «Последняя строка», «Соединение строк» | Поля правого набора и реквизиты его ссылочных полей | `НаборыДанных.[Набор].[Соединение].[Поле]` |
| «Многострочная коллекция» | Количество строк и итоги по числовым колонкам: сумма, среднее, максимум, минимум | `НаборыДанных.[Набор].[Соединение].КоличествоСтрок`, `НаборыДанных.[Набор].[Соединение].Итог.[Поле].[Агрегат]` |

Особенности:

* у соединения «Многострочная коллекция» нет полей отдельных строк — строк много, и одно значение из них не выбрать. Если нужно значение одной строки, задайте соединению вид «Первая строка» или «Последняя строка»;
* «Итог накопительный», «Итог по странице» и «Процент к итогу» под соединением не предлагаются: они считаются по мере вывода строк и есть только у самой многострочной коллекции;
* если левый набор — многострочная коллекция, соединение относится к каждой её строке: в путь после имени набора входит `.Строка` (`НаборыДанных.Товары.Строка.Остатки.Итог.Остаток.Сумма`), и такие поля доступны в области, которая выводится по строкам этой коллекции;
* через ссылочное поле соединения доступны его реквизиты — так же, как у поля самого набора;
* по имени параметра поля соединений не подставляются, см. [Заполнение по имени](/guide/ch-02-07/#заполнение-по-имени).

![](/img/ch_02/99_fields_tree_joins.png)
    
Соединение «ТоварыПерваяСтрока» с видом «Первая строка»: узел с именем соединения и поля правого набора

### Пример: товары в шапке счёта

В макете счёта есть набор «Шапка» с видом «Первая строка» и набор «Товары» с видом «Многострочная коллекция». К шапке подключены два соединения по полю «Ссылка»: «ПервыйТовар» с видом «Первая строка» и «Строки» с видом «Многострочная коллекция». Тогда в области шапки доступны:

| Путь | Что выведется |
|--|--|
| `НаборыДанных.Шапка.ПервыйТовар.Номенклатура` | Номенклатура первой строки товаров |
| `НаборыДанных.Шапка.ПервыйТовар.Номенклатура.Артикул` | Артикул этой номенклатуры |
| `НаборыДанных.Шапка.Строки.КоличествоСтрок` | Количество строк товаров, отобранных соединением |
| `НаборыДанных.Шапка.Строки.Итог.Сумма.Сумма` | Сумма колонки «Сумма» по этим строкам |

## Склонение представлений

Русский текст в печатных формах часто требуется в косвенном падеже: «в лице генерального директора Иванова Ивана Ивановича», «выдана Петровой Марии Сергеевне». Отдельного поля для этого не нужно — склонение входит в настройки [форматирования строки](/guide/ch-02-12/#формат-строки) и применяется к любому строковому значению: параметру области, полю представления, полю набора.

Настройка находится на закладке «Строка» конструктора форматирования, в группе «Склонение в падеже», и состоит из трёх частей:

| Настройка | Назначение |
|--|--|
| Падеж | Падеж, в который нужно просклонять значение. Если падеж не выбран, склонение не выполняется |
| как ФИО | Флажок. Признак того, что значение — фамилия, имя и отчество; включает режим склонения ФИО |
| пол | Уточнение рода: «авто», «мужской» или «женский». Учитывается только при установленном флажке «как ФИО» |

Доступные падежи:

| Падеж | Значение в XML |
|--|--|
| Именительный | `Nominative` |
| Родительный | `Genitive` |
| Дательный | `Dative` |
| Винительный | `Accusative` |
| Творительный | `Instrumental` |
| Предложный | `Prepositional` |

Значения настройки «пол» в файле выгрузки — `Auto`, `Male`, `Female`. Значение «авто» означает, что род определяется автоматически по самому ФИО.

### Пример: ФИО в родительном падеже

Требуется вывести «Доверенность выдана Иванова Ивана Ивановича» — фамилию, имя и отчество в родительном падеже.

1. В таблице параметров области находим параметр с ФИО и двойным кликом по крайней правой колонке открываем настройку форматирования.
2. Переходим на закладку «Строка» и в группе «Склонение в падеже» выбираем падеж «Родительный».
3. Устанавливаем флажок «как ФИО».
4. Если автоматическое определение рода даёт неверный результат (например, для редких или несклоняемых фамилий), задаём пол явно.

![](/img/ch_02/86_format_declension.png)
    
Склонение в падеже на закладке «Строка» конструктора форматирования

Склонение выполняется до форматирования ФИО по шаблону, поэтому настройки «Склонение в падеже» и «Вариант вывода ФИО» можно использовать вместе: сначала значение склоняется целиком, затем сокращается до нужного шаблона (например, «Иванова И. И.»). Полный порядок операций форматирования приведён в разделе [Форматирование](/guide/ch-02-12/#порядок-обработки).

:::note
Если флажок «как ФИО» не установлен, значение склоняется как обычное представление — например, наименование должности или организации.
:::

## Системные поля

:::note[Доступно с версии 2026.2.11]
:::

Системные поля — это набор `НаборыДанных.СистемныеПоля`, который программа формирует сама. Его не нужно создавать, он всегда присутствует в дереве доступных полей и не зависит от запросов макета.

| Поле | Тип | Что содержит |
|--|--|--|
| `НаборыДанных.СистемныеПоля.НомерСтраницы` | Число | Номер текущей страницы печатной формы |
| `НаборыДанных.СистемныеПоля.ТекущаяДата` | Дата | Дата и время формирования печатной формы |
| `НаборыДанных.СистемныеПоля.ТекущийПользователь` | Ссылка | Пользователь, сформировавший печатную форму (доступно при использовании подсистемы «Пользователи» БСП) |

Системные поля используются так же, как обычные: подставляются в параметры областей, в конструктор представления и в правила вывода. Типичные сценарии — нумерация страниц в области, повторяемой в подвале, отметка «Сформировано <дата>» и условный вывод области начиная со второй страницы. Для колонтитула на полях листа системные поля не нужны: там работают конструкции платформы, см. [Колонтитулы](/guide/ch-02-14/#колонтитулы). Пример правила вывода с полем `НомерСтраницы` разобран в разделе [Макет](/guide/ch-02-07/#условия-вывода-области).

К полю `ТекущаяДата` применимы функции поля даты — например, `НаборыДанных.СистемныеПоля.ТекущаяДата.НачалоДня` даёт дату формирования без времени.
